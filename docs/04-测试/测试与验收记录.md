### 真实故障复盘:「复制只修好一半」(2026-10-21)

**现象**:学习通测验页复制,前半句是明文、后半句仍是密文:

```
【单选题】固定导轨的安装扣最先在()的安装上使用。            ← 修好了
【判断题】一旦有人提出无抲宣告请求,专利局抸者法抶就必曳抷理。  ← 抲抸抶曳抷 没修
```

**排查过程**(每一步都有实测):

| 假设 | 验证方式 | 结果 |
| --- | --- | --- |
| 映射表里没有这些字 | 导出映射表全表 | ❌ 表里**有**(抲→效、抸→或、抶→院、曳→须、抷→审) |
| 作用域有多个、查错了表 | 逐 frame 导出作用域与映射 | ❌ 全页**只有一个** `@font-face`、一个作用域、19 条映射 |
| 字体被换了、指纹变了 | 对比 @font-face 与作用域指纹 | ❌ 指纹稳定(`font-cxsecret#datalzv4nl`) |
| **作用域缓存没赶上选区** | 清空采集缓存后立刻复制 | ✅ **命中** —— 不修的正是"没被采集过的新密文字" |

**根因**:映射表按字体整份下发(是对的),但"这个字属于哪个字体作用域"
存在**采集缓存**里,采集比复制慢一拍 → 新选区里的密文字查表落空 → 原样进剪贴板。

**修复**:守卫 v6 —— 复制时**当场**按当前选区从 DOM 现算作用域(ADR-0005)。

**红/绿对照**(仓库自带闭环测试 `loop.cjs` 阶段3,选一段从未采集过的新密文字并立即复制):

| 守卫 | 剪贴板 | 结论 |
| --- | --- | --- |
| v5(旧) | `闰余成岁律吕调阳云腾致雨露结为霜金生丽水玉出昆冈` | ✖ 原样密文 |
| v6(新) | `推理应用场景需求用户体验设计开发测试部署运维监控` | ✔ 全部还原 |

### 通用性专项(2026-10-21):修法必须对"没给过的场景"也成立

用户明确要求:不能只对给的那几道题成立。做法是**自己造用户没给过的用例**并做成常驻回归测试。

#### 发现并修掉的两个"只在那几道题上成立"的问题

| # | 问题 | 旧行为 | 新行为 | 用例 |
| --- | --- | --- | --- | --- |
| 1 | 查表按**字符身份**(一个字只对应一个作用域) | 同一个字出现在密文与普通两种作用域时,普通那处被一起改掉 → **写出错字**(实测「人人」) | 按**出现位置**(逐个文本节点)判定,各查各的表 | `generality.cjs` s1/s2 |
| 2 | 参考库只含 GB2312 | 库里缺的生僻字被认成形近的错字 → **写出错字**(燚→焱、垚→寺、鿕→鲋、㶿→饽) | 参考库换 GBK 全集(gzip 9.7MB),真答案在库里;认不出的被闸门挡住 | `tools/lab/probe-missing-char.cjs` |

**为什么第 2 条不能用"提高阈值"糊过去**:真实字体的逐字分数最低只有 0.8881,
而缺字错配的分数是 0.81~0.90 —— 区间重叠,阈值分不开"真匹配"与"缺字错配"。

#### 顺带修好的一个对齐坑

复制时要按"片段"替换,但浏览器的 `selection.toString()` 是**渲染后的文本**(空白按 CSS 折叠),
文本节点原文里却带着制表符、缩进换行 → 直接比对必然对不上(实测整页选中时第一段就断)。
改成**只比对非空白字符**、输出仍用浏览器那份文本(排版不变)后解决。

### 为什么「坉」判不出来(实测,不是猜)

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 参考库里没有「略」 | 查 GBK 库 | ❌ 有 |
| 4bit 量化导致 | 全精度重算 | ❌ 0.1288 vs 0.1276,几乎一样 |
| 分辨率不够 | 48/64/96 三档 | ❌ margin 0.0156/0.0137/0.0151,基本不变 |
| 粗筛筛掉了正确答案 | 查粗筛排名 | ❌ 排第 1、2 名 |
| margin 闸门太严 | 读引擎判定 | ✅ 命中 |

顺带挖出两个真 bug:

1. **「常用字优先」这个判定从来没生效过**:`COMMON_SET` 存的是**字符串**,
   候选的 codepoint 是**数字** → `has()` 永远 false → 从写下来那天起就是空转的。
2. **margin 闸门把生僻字也当成了同样说得通的竞争者**:
   格(木各)/挌(扌各)/恪(忄各)像素上几乎一样(0.8496 vs 0.8472),
   但字频分得开 → 改成**给常用字先验加分并参与 margin 计算**。
   修完:圻→**格** ✓ 还原了。

「坉」仍然判不出来,因为站点重绘后的「略」像素**离「赂」更近**(0.1007 vs 0.1162),
**像素里没有答案**,只能靠语境("战X管理能力"→战略),本版未做 →
系统**保守不改**(留密文码位,不写错字)。

### 换题回归(新增,2026-10-21)

用户每换一套题就换一套加密字体。这条测试专门盯这件事:
**同一个标签里来回换字体(A→B→A→B)**,两套字体码位相同、画成不同的字
(旧映射泄漏的话答案会明确错掉)。

| 场景 | 结果 |
| --- | --- |
| 第 1 题(A) | ✔ |
| 换题 A→B | ✔ |
| 换题 B→A | ✔ |
| 连续换题 A→B→A→B | ✔ 3/3 |

**这条测试第一次跑就抓出两个真 bug**(见 ADR-0009):
① 预热与选区用了不同阈值 → 换题后"选中就立刻复制"必然缺字
② 站点重绘笔画更细 → 灰度距离偏向笔画少的字(「略」被认成「赂」)

### 根因(ADR-0010)要点

| 观测 | 数值 |
| --- | --- |
| 失败字在不在库里 | **都在**(参考库是 GBK 全集 21517 字) |
| 墨量比(站点 vs 参考) | **0.880**,25 个码位全在 0.80~0.91 → 系统性变细 |
| 宽比/高比、重心偏移 | 1.00/0.98、≈0px → 几何完全一致 |
| 病根 A | 像素距离偏爱"笔画少"的字 → 「略」输给「赂」 |
| 病根 B | 库里有只差一笔的孪生字(国/囯)→ margin 0.0100 → 被闸门挡 |

**教训**:通用不是多写几个用例,而是找到那个**可被度量解释的系统性差异**。
前面几次都在阈值和规则层面打转,真正根因是**度量的量纲错了**。

### 换题后的"映射就绪窗口"(2026-10-21 晚)

复现:同标签内换字体 → 立刻复制。

| 时刻 | 剪贴板 |
| --- | --- |
| 换题后立刻 | **原始密文**（"天地玄黄宇宙洪荒日月盈昃…"） |
| 换题后第 1 轮 | ✔ 正确（1956ms） |

**=> "换题就失败"的机制:不是识别不准,是新字体的映射还没建好。**
修:① 预热与选区统一阈值(之前预热 0.88 / 选区 0.8,预热那张表少几条)
② 给"带混淆字体的标签"单开快轮询(~200ms)→ 就绪时间 2.0s → **0.5s**

### 明文到底在不在浏览器里(实测)

穷举搜过:DOM / 所有属性 / `<script>` / 输入框值 / 注释 / `window` 全局 → **没有明文**。
同源接口响应里也是密文(`aria-label='A 企嵻嵽嵼选择'`)。
**=> 混淆是服务端做的,明文从没到过浏览器**;页面里"正确"的只有字体里的字形和屏幕像素,
而像素路径拿到的形状信息与字形路径完全相同 → 反推字形是唯一可行路径。

### 验收判定自身的坑(已修)

`tools/verify/verify-app-e2e.cjs` 原先用 Unicode 区段(U+3400–U+4DBF)猜"密文字",
而学习通真实密文字在 **U+62xx / U+66xx / U+78xx**(抲 U+62B2、抸 U+62B8、曳 U+66F3)
→ **完全落在那个区段之外 → 永远判定为 0 → 假通过**。
现改为按**页面里实际下发的映射表**判定(表里的键 = 被混淆的码位),
并追加"明文片段命中"作为独立交叉验证。

### 一次假失败的排查(2026-10-21 收尾时)

清理过程中 `npm test` 出现过一次 `loop.cjs` 阶段3 失败
(「新选区的密文字没被还原(作用域查表落空)」)。**不是回归**,是环境干扰,证据链:

1. 复跑时剪贴板里是 **测试自己写的哨兵 `SENTINEL`** —— 说明 `document.execCommand('copy')`
   **根本没执行**,浏览器根本没被要求复制。不是「复制了但内容不对」。
2. 协调器状态里 `safariFrontmost: false` —— 守卫**只在 Safari 位于前台时才注入**
   (「前台才动作」是设计,见 [ADR-0004](../06-决策/ADR-0004-按站点URL覆盖标签而非只管前台.md))。
   人在同时用别的 App / 把 Safari 窗口关掉时,这条链路整个不成立。
3. 连续复跑 3 次:第 1 次失败(剪贴板=SENTINEL、且遗留一个窗口),
   第 2、3 次 **阶段 1/2/3 全过**。
4. 失败那次剪贴板里是 `Campus-Network-Connector` —— 那是**用户在别处复制的仓库目录名**,
   属于外部写入,与测试无关。

> **判据(以后遇到同类假失败照这个分)**:剪贴板里如果是**测试自己写进去的哨兵值**
> → 复制压根没发生 → 查环境(Safari 在不在前台、窗口在不在);
> 如果是**别的内容** → 外部进程写了剪贴板 → 查是谁写的;
> 只有剪贴板里是**页面的原始密文** → 才轮到怀疑代码。

> 该用例失败时还会留下一个 Safari 窗口(自建窗口的分支在异常路径上没走到清理)。
> 事后按 URL 精确定位并删掉:窗口里 `URL contains "127.0.0.1"` 的那个标签。
>
> **套件里第一个碰 Safari 的用例(`generality.cjs`)最敏感**:它跑在 `cleanup.cjs` 之后,
> 需要自己把 Safari 抢到前台;后面几个用例(`loop` / `switch-quiz` / `iframe-case`)都过,
> 说明链路本身没问题。**判据:单独跑它能过、套件里第一个跑就挂 → 判环境,别改代码。**
> 单独跑:`node src/features/safari-repair/test/generality.cjs`(实测 7/7 全过)。

### 「第一次成功、后两次失败」的真根因(ADR-0015)

**现象**:用户报「第一次成功,后两次失败」,并怀疑「题目被写死过」。
**「写死」这个猜测是错的** —— 全仓核对**没有任何写死的字→字映射**。
真实原因是:第一份字体的**分析结果被缓存**了,换到新字体(新的 data URI)
就是缓存不命中,又要等一遍分析。

在真实学习通测验页上逐层拆,查出**三处断点**(都不是"写死"):

| # | 断点 | 查到的证据 | 修法 |
| --- | --- | --- | --- |
| 1 | **判活查询依赖 System Events** | `lastError` = "Safari 未运行",而 Safari 明明开着 19 个标签;`poll.lastProbe` **全空**(一次都没成功读到过标签) | 改用 `application "Safari" is running`;问不到 ≠ 没运行;Safari 没开是中性状态 |

| 3 | **字体分析串行** | 新字体首次分析很慢(当时实测 11 秒),这期间页面上没有映射 | rayon 并行;**判定口径一字未改**,字体级闸门(宁可留错字绝不写错字)**没放松**。⚠️ 后来查明那两个数是 **debug 构建**量的,release 下同一份真机字体只要 **13ms** —— 真正的瓶颈是下发延迟(ADR-0016) |

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 题目那层(`top>1>1>1`)映射数 | **0** | ✅ 10 层 frame 全部拿到映射(**33 个字**) |

## 验收记录(2026-10-23 晚)

### 「两三次错一次」的根因与修复(ADR-0016)

**现象**:用户复测「效果比刚才好,但依然是两三次中间出现了一次错误」,
怀疑"需要的时间还是偏长"。

**先证伪"分析慢"**:在同一份真机字体夹具 + 同一份参考库上逐段量两个引擎 ——
Rust(release)**13.4ms / 23.0ms** vs Electron(JS)**157ms / 248ms**。
**Rust 快 12 倍,分析根本不是瓶颈。**
(顺带发现 ADR-0015 里"11 秒 → 2.5 秒"那两个数是 **debug 构建**量的,
debug 比 release 慢 **25 倍** —— 那个数从来不是用户等的东西。)

**真凶**:一次 Apple Events 往返 ≈110ms(每次新起 osascript 进程),
而 Tauri 的轮询是**一条串行通道**:判活(110ms) → 列全部标签(110ms)
→ 目标站点标签**每 2 轮**才处理一次 → 实际 **~1 秒**才看一眼目标标签。
Electron 有**独立的 200ms 快轮询**,Tauri 移植时压成了单通道。

**"两三次错一次"的来历**:目标标签每 2 轮才被看一眼 → 大约一半的切题时刻
落在"还没轮到"的那一轮 → **失败率天然 ≈50%**,是有周期的,不是随机故障。

**修复**:补一条同形状的快通道(200ms、只盯建出过映射的标签、不判活不列标签),
主通道让位但靠心跳兜底(快通道死了主通道自动接管),
同一标签用处理权锁互斥;顺带把 `FastGlyphMatcher` 改成全局只建一次
(原先每次 `check_tab` 都克隆 9.7MB 的库并重建索引,**36ms/次**)。

**A/B 实测**(同一台机器、同一个页面、同一个探针、同样的安装流程,
唯一差别 = 有没有快通道;测法 = 清空映射 + 撤掉选区触发重新上报,
再轮询题目那层 frame 的 mappings 从 0 变成 >0 的时刻):

| | 改之前 | 改之后 |
| --- | --- | --- |
| 映射下发耗时 | 1605 / 2379 / 2619 / 2173 ms | **87 / 403 / 532 / 258 / 563 / 396 / 409 / 390 / 420 / 397 ms** |
| 均值 | **≈2194ms** | **≈320ms**(快 6.9 倍) |
| 端到端复制 | 常常复制出密文 | 剪贴板**无残留密文字**(连续 6/6 次) |

**回归测试**:`cargo test --lib` **16/16**(新增 4 条:快通道登记/摘除、
同一标签只允许一条通道处理、**快通道死了主通道要接管**、目标标签每两轮才进主通道)。

**新装的包的现场自检**:
`fastPoll: {"alive": true, "cipherTabs": 1, "heartbeats": 20, "intervalMs": 200}`。

## 界面注释对齐 + 交付脚本修正(2026-10-24 收尾)

### 一、修掉的 4 处矛盾说法

| 原来的说法 | 在哪 | 为什么错 | 现在改成 |
| --- | --- | --- | --- |
| 「Windows 版到「默认执行」为止,少两个界面但功能不缺」 | 两仓 `App.jsx` | Windows 补上「键盘输入」这一步后是 **3 步**(激活 + 默认执行 + 键盘输入) | 「「模拟点击(录制)」这一步是 macOS 专属…下面的「键盘输入」两边都有」 |
| 「Windows 版**只有这两步**…快捷输入是 macOS 专属能力」 | 两仓 `DefaultExecutePanel.jsx` | ADR-0012 明确**保留** Windows 的拼音自动键入(直接送 Unicode 字符) | 「Windows 版比 macOS 少「录制」这一步…但**保留**「键盘输入」」 |
| 「Windows 版没有录制能力」/「Windows 线**也有录制**,所以这个面板在两边**行为一致**」 | 两仓 `ClickPanel.jsx` | 两种说法**互相矛盾**,而且都不对:面板由 `!isWindows` 挡着,**Windows 上根本不出现**;按 ADR-0012,Windows 侧不做录制入口 | 「Windows 按 ADR-0012 不做录制入口(界面上不露出)」 |
| 「与 mac 分支**逐字一致**」「与 mac 分支保持一致」 | 两仓 `App.jsx` | 自指 —— 现在两个分支是**同一份文件** | 「两个平台…」 |

Electron 的 win 分支另外落下两处,一并补回 mac 版:

- `App.jsx` 的「辅助功能」小问号:win 侧写死 `showAccessibilityBadge: false`,mac 侧用 `isMac`
  ⇒ 统一成 `isMac`(Windows 上 `isMac` 恒为 `false`,**行为不变**),
  顺带补回 win 侧没有的 `onOpenAccessibilitySettings`;
- `FeatureToggles`:win 侧少了「失败原因」与「Safari 未运行」的显示
  ⇒ 用 mac 版(Windows 上功能清单为空,渲染结果不变,但以后 Windows 加功能不会再漏)。

### 二、字节一致基线(本轮实测)

「行为一致」不能靠人肉保证 —— 判据是**逐字节**比对:

| 仓库 | mac vs win 共享界面文件 | 不一致的 |
| --- | --- | --- |
| Tauri | **16 / 17 相同** | `src/tauri-bridge.js`(平台桥接:CGEventTap ↔ Win32 钩子,**平台必需**) |
| Electron | **16 / 16 相同** | 无 |

行为核心仍然是字节相同:

- Tauri `tauri-app/src-tauri/src/commands/native/hotkey_core.rs` — mac 与 win sha256 一致
- Electron `shortcut-latch.cjs` / `tools/verify/verify-shortcut-latch.cjs` — mac 与 win sha256 一致

构建产物层面:

- **Electron:两个分支构建出的前端 bundle 哈希相同**(`index-DNilihZu.js`)
  ⇒ 界面已经是**同一份产物**。这是本轮补齐那两处等价写法之后的直接结果
  (补齐前 win 是 `index-srad3i1t.js`,与 mac 不同)。
- Tauri:两个分支的 bundle 不同(`index-B1wuDYOw.js` / `index-BJHIglMc.js`),
  差异**全部**来自上面那一个平台桥接文件。

### 三、交付脚本的两处修正(`tools/lab/package-deliverables.cjs`)

1. **挑 Windows 产物会挑错**。脚本原本按 release 的 `createdAt` 排序取「最后一个」。
   同一批 release 常常是**同一秒创建** ⇒ `createdAt` 并列 ⇒ 稳定排序保留 `gh` 的原序,
   取到的「最后一个」是并列里**最旧**的 ⇒ **把旧包当成最新包发给用户**。
   实测:旧逻辑在 tauri 仓会选 `win-tauri-40056800017`,而当时最新的是
   `win-tauri-40058093082` —— **差了两个 run**。
   ⇒ 改成按标签末尾的 **run_id**(GitHub Actions 的 run id,单调递增)排序,
   `createdAt` 只作 run_id 缺失时的兜底。拿真实 release 列表验过:两个仓都选中最大 run_id 那个。
2. **dmg 清理收窄**。以前是「桌面上所有 `*.dmg` 一律移进回收站」——
   用户从别处下载的 dmg 会被这个脚本弄没。现在只清**本项目**的
   (文件名含 `模拟输入` / `SimuInput`),别人的一律保留,并打印一行说明。

顺带把 win 分支那份**旧版**脚本同步成 mac 版(它还产出已废弃的
`模拟输入-win-x64-安装包.zip`、只含一个 exe)⇒ 两仓两分支四份逐字节相同。

## 验收记录(2026-10-24 晚):Windows 三项 —— 撤掉「默认执行」界面 / 红底白字横幅 / 偏卡顿

用户反馈(均为 **Windows 版**):

1. Tauri 版「页面摘除不够干净」,多出一个**不能执行**的「默认执行」界面;
2. Tauri 版对这个**本来就没有的功能**显示**红底白字**提醒,要求去掉;
3. Electron 版没有红底白字问题,但**一样多了一个界面**(与 Tauri 相同);
4. Tauri 版**偏卡顿**。

### 三条根因(都不是"忘了删")

| 现象 | 根因 | 证据 |
| --- | --- | --- |
| ①/③ 多一个界面 | Windows 线**不做录制** ⇒ 没有可回放的源 ⇒ 「默认执行」那一屏是**死界面** | ADR-0012 当初写「保留默认执行(回放)」,前提(「录制文件跨平台」)在 Windows 上不成立 |
| ② 红底白字必现 | `get_native_status` 的 `ok` 写成了 `cfg!(target_os = "macos")` —— 是「**是不是 macOS**」而不是「**原生模块能不能用**」 | Electron 那边是 `ok: !!native` ⇒ 两个字段**同名不同义** |
| ④ 偏卡顿 | 窗口高度**既由视口决定、又反过来决定视口**:内容区 `max-height:65vh` ↔ 运行时 `set_size`;Windows 窗口起始只有 320 高(mac / Electron 都是 640)⇒ 一格一格往上爬(推导值,非实测) | `src/components/Stepper.jsx` 的 `maxHeight:'65vh'` + `src/tauri-bridge.js` 的 `fitWindow` + `tauri.windows.conf.json` |

### 改了什么

| 项 | 之前 | 之后 |
| --- | --- | --- |
| Windows 界面步骤 | 激活 → 默认执行 → 键盘输入(3 步) | **激活 → 键盘输入(2 步)** |
| Windows 界面上有「默认执行 / 选择录制 / 管理」 | 有 | **没有** |
| 原生状态的 `ok` | `cfg!(target_os="macos")`(Windows 恒 false) | `NATIVE_MODULE_SUPPORTED`(Windows = true,与 Electron 同口径) |
| 横幅出现的条件 | Windows 上**必然**出现 | 只在原生模块**真的坏了**时出现(而且写明原因) |
| 窗口贴合内容 | 按「当前渲染出来的高度」算 ⇒ 与窗口高度绕圈 | 按**内容的自然高度**算 ⇒ 一次算准,切页动画期间不再触发 resize |
| Windows 窗口起始高度 | 320(启动时内容装不下) | **640**(与 macOS / Electron 对齐) |
| 目标高度没变时 | 每次都 IPC 叫原生改窗口 | 不再叫(原生那边每次要枚举显示器,不免费) |

### 门禁(本轮新增 / 改写)

- Rust 单测 `native_status_tests`:`ok` 的口径(2 条)——
  `cargo test --lib` **33 / 33**(win 分支)、**53 / 53**(mac 分支)。
- 界面门禁 `verify-ui-platforms.cjs`:Windows **2 步**、界面上没有「默认执行 / 选择录制 / 管理」、
  第 2 步是「键盘输入」且有「开始输入」按钮、**模块正常时没有红底白字横幅**。
  另外加了一条**反向**用例:桩里把 `ok` 设成 `false` ⇒ 横幅**必须出现**且写明原因
  (免得横幅变成死代码)。
- 门禁结果:Tauri mac / win、Electron mac / win 四个工作副本**全过**。

### 怎么在 Windows 上自己验「卡顿」修没修

原生侧记了一个 `FIT_RESIZE_COUNT`:**实际**改过几次窗口尺寸,
出现在 `get_native_status` 的 `fitResizes` 字段 ⇒ 前端每 3 秒写的 `diag.json` 会带着它。
**切一步应该只 +1**;还是一串数字 ⇒ 贴合内容那条链还在绕圈。

### 没做的 / 待拍板

- **⌃S 全局快捷键仍注册在 Windows 上**,而它驱动的正是「默认执行」——
  现在那一屏在界面上已经没有了,⌃S 变成驱动一个**看不见的动作**的全局键,
  而且会**抢走别的 App 的 Ctrl+S**。本轮**没动**(改全局键属于改行为,要有单独授权)。
  ⌃D(读剪贴板并键入)保留 —— 那条走的是「键盘输入」,是真功能。
- **Windows 真机行为仍未验证**(本仓库的验证环境是 macOS)。CI 只证明「编得过 + 门禁过」。
- macOS 线的「窗口贴合内容」有**同一个圈**,但它的窗口起始高度够大、一次就到位,
  本轮**没动**(改了会让已交付的 mac 包变旧)。记在 `docs/05-运维/已知限制与失败场景.md`。

## 验收记录(2026-10-24 晚续):Windows 三项 —— 不占用系统默认快捷键 / 关窗口不退出 / 右上角三按钮

对应 **ADR-0027**。Electron 侧有**同编号**的 ADR-0017,两边行为一致。

### 用户提的三件事(原话)

1. 「Windows 电脑上 tmd Ctrl 加 D 是系统默认的按钮,我不能设置为快捷键,不然他直接把软件退出了」
2. 「你不能点叉,他就直接完全退出了,这个他要在后台挂着,功能依然生效呀」
3. 「或者你把它右上角做一个三个按钮,就是最大化最小化或者说直接关掉,别只留一个关掉的按钮」

### 改了什么

| 项 | 之前 | 之后 |
| --- | --- | --- |
| 系统全局热键(Windows) | 注册 ⌃S / ⌃D | **一个都不注册** |
| 窗口内 keydown | 拦 ⌃S(⌃D 原本已禁) | **不拦** —— 两个键就是普通按键 |
| Control 观察线程 | 每 20ms 轮询 `GetAsyncKeyState` | **不启动**(只服务于全局键的 latch) |
| 点右上角那个 ✕ | **直接退进程** | **隐藏窗口**,进程留着 |
| 系统级关闭(Alt+F4 / 任务栏→关闭窗口) | 关窗口 = 退进程 | **只隐藏**,不退出 |
| 彻底退出的入口 | 右上角那个 ✕ | **托盘菜单的「退出程序」** |
| 右上角按钮 | 1 个(✕) | **3 个**:最小化 / 最大化(再点还原)/ 关闭 |
| 「读剪贴板并键入」的入口 | ⌃D 全局键 | **「键盘输入」页的按钮** |
| 托盘图标 | 没有 | **有**(左键=叫回窗口;右键菜单=显示窗口 / 退出程序) |
| 诊断里的快捷键字段 | `registered` / `ctrlS` / `ctrlD` | 加一栏 **`globalShortcutsEnabled: false`** |

### 门禁(本轮新增)

- **Rust 单测** `shortcut_tests::Windows线不注册任何全局快捷键`:
  注册清单必须是空的 + 观察器开关必须是关的。
  → `cargo test --lib` **34 / 34**(win 分支;改之前 33 / 33)。
- **界面门禁** `verify-ui-platforms.cjs` 新增 6 条断言:
  1. 右上角有 3 个按钮;
  2. 三个按钮依次是「最小化 / 最大化 / 关闭」;
  3. 点它们分别调 `minimize` / `maximize` / `hide`;
  4. **「关闭」不调 `quit`**;
  5. 「键盘输入」页有「从剪贴板读入并键入」按钮;
  6. 点它**真把剪贴板里的字送进键入通道**。
  另外加一条**源码级**断言:全局快捷键的开关是关的(界面上看不出系统里注册了哪些键)。
- 门禁结果:本机 `node --test`(win 分支 32 项)+ `cargo test --lib`(34 项)+
  `verify-ui-platforms.cjs` 全过;Electron win 分支 `node --test` 37 项 + 界面门禁全过。

### 怎么在 Windows 上自己验(真机三条)

1. **不抢系统键**:开着 Word / 记事本,按 ⌃D ⇒ 正常删字 / 正常触发系统菜单,
   **不是**被我们的 app 吃掉。
2. **关窗口不退出**:点右上角 ✕ ⇒ 窗口消失、**任务栏没有图标**、但
   **托盘区(右下角)有图标**;左键点它 ⇒ 窗口回来。
3. **彻底退出**:托盘右键 →「退出程序」⇒ 进程真的没了(任务管理器里也没有)。

### 没做的 / 待拍板

- **Windows 上不再有任何全局快捷键**。以后要加,必须是**不与系统默认键冲突**的组合
  (键位由用户拍板;用户此前明确拒绝过 Shift 组合)。
- **Windows 真机行为仍未验证**(本仓库的验证环境是 macOS)。CI 只证明「编得过 + 门禁过」。
  上面那三条真机验收**要用户自己在 Windows 上过一遍**。
- macOS 线**一行没动**:仍是 4 步、仍用原生红绿灯、仍注册 ⌃S / ⌃D。

## 补记(2026-10-25):「从剪贴板读入并键入」必须等 3 秒,不能立刻键入

用户追问「怎么保证我的软件功能确实可以执行」时,顺着链路查下去发现这个按钮第一版写错了。

**问题**:点我们按钮的那一刻,焦点在**我们自己的窗口**里。
立刻键入(`pinyinInput(text, 0, false)`)⇒ 字被送进**我们自己的界面**,
而不是用户想输入的那个目标软件 —— 字就丢了。

两个框架的表现还不一样:

| | `delay = 0` 的实际行为 |
| --- | --- |
| Electron | `if (delaySeconds > 0)` ⇒ **真的立刻** ⇒ 隐患是活的 |
| Tauri | `Number(delaySeconds \|\| 3)` ⇒ `0 \|\| 3` = **3** ⇒ 碰巧挡住了 |

⇒ Tauri 那边不是「本来就对」,是**一个 bug 正好挡住了另一个 bug**。

**改法**:这个按钮改走**和「开始输入(3s 后键入)」同一个函数**(`requestPinyinInput`)
⇒ 3 秒倒计时 + 界面提示「3 秒后开始输入,请将光标移动到目标位置」。
Tauri 桥接层的 `|| 3` 改成 `??`(显式传 0 就是「不要等」)⇒ 两边口径一致
(Tauri 侧顺带修掉了 mac 线同一个隐患:原来传 0 会被当成 3 秒)。

**门禁**:界面门禁加 2 条断言 —— `pinyinInput` 收到的延迟**必须是 3**、
界面上**必须有倒计时提示**(旧实现传 0 ⇒ 两条都转红)。
