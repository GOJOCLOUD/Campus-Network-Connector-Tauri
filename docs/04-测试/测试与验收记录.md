### 真实故障复盘:「复制只修好一半」(2026-10-21)

**现象**:学习通测验页复制,前半句是明文、后半句仍是密文:

```
【单选题】固定导轨的安装扣最先在()的安装上使用。            ← 修好了
【判断题】一旦有人提出无抲宣告请求,专利局抸者法抶就必曳抷理。  ← 抲抸抶曳抷 没修
```

**排查过程**(每一步都有实测):

| 假设 | 验证方式 | 结果 |
| --- | --- | --- |
| 映射表里没有这些字 | 导出映射表全表 | ❌ 表里**有**(抲→效、抸→或、抶→院、曳→须、抷→审) |
| 作用域有多个、查错了表 | 逐 frame 导出作用域与映射 | ❌ 全页**只有一个** `@font-face`、一个作用域、19 条映射 |
| 字体被换了、指纹变了 | 对比 @font-face 与作用域指纹 | ❌ 指纹稳定(`font-cxsecret#datalzv4nl`) |
| **作用域缓存没赶上选区** | 清空采集缓存后立刻复制 | ✅ **命中** —— 不修的正是"没被采集过的新密文字" |

**根因**:映射表按字体整份下发(是对的),但"这个字属于哪个字体作用域"
存在**采集缓存**里,采集比复制慢一拍 → 新选区里的密文字查表落空 → 原样进剪贴板。

**修复**:守卫 v6 —— 复制时**当场**按当前选区从 DOM 现算作用域(ADR-0005)。

**红/绿对照**(仓库自带闭环测试 `loop.cjs` 阶段3,选一段从未采集过的新密文字并立即复制):

| 守卫 | 剪贴板 | 结论 |
| --- | --- | --- |
| v5(旧) | `闰余成岁律吕调阳云腾致雨露结为霜金生丽水玉出昆冈` | ✖ 原样密文 |
| v6(新) | `推理应用场景需求用户体验设计开发测试部署运维监控` | ✔ 全部还原 |

### 通用性专项(2026-10-21):修法必须对"没给过的场景"也成立

#### 发现并修掉的两个"只在那几道题上成立"的问题

| # | 问题 | 旧行为 | 新行为 | 用例 |
| --- | --- | --- | --- | --- |
| 1 | 查表按**字符身份**(一个字只对应一个作用域) | 同一个字出现在密文与普通两种作用域时,普通那处被一起改掉 → **写出错字**(实测「人人」) | 按**出现位置**(逐个文本节点)判定,各查各的表 | `generality.cjs` s1/s2 |
| 2 | 参考库只含 GB2312 | 库里缺的生僻字被认成形近的错字 → **写出错字**(燚→焱、垚→寺、鿕→鲋、㶿→饽) | 参考库换 GBK 全集(gzip 9.7MB),真答案在库里;认不出的被闸门挡住 | `tools/lab/probe-missing-char.cjs` |

**为什么第 2 条不能用"提高阈值"糊过去**:真实字体的逐字分数最低只有 0.8881,
而缺字错配的分数是 0.81~0.90 —— 区间重叠,阈值分不开"真匹配"与"缺字错配"。

#### 顺带修好的一个对齐坑

复制时要按"片段"替换,但浏览器的 `selection.toString()` 是**渲染后的文本**(空白按 CSS 折叠),
文本节点原文里却带着制表符、缩进换行 → 直接比对必然对不上(实测整页选中时第一段就断)。
改成**只比对非空白字符**、输出仍用浏览器那份文本(排版不变)后解决。

### 为什么「坉」判不出来(实测,不是猜)

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 参考库里没有「略」 | 查 GBK 库 | ❌ 有 |
| 4bit 量化导致 | 全精度重算 | ❌ 0.1288 vs 0.1276,几乎一样 |
| 分辨率不够 | 48/64/96 三档 | ❌ margin 0.0156/0.0137/0.0151,基本不变 |
| 粗筛筛掉了正确答案 | 查粗筛排名 | ❌ 排第 1、2 名 |
| margin 闸门太严 | 读引擎判定 | ✅ 命中 |

顺带挖出两个真 bug:

1. **「常用字优先」这个判定从来没生效过**:`COMMON_SET` 存的是**字符串**,
   候选的 codepoint 是**数字** → `has()` 永远 false → 从写下来那天起就是空转的。
2. **margin 闸门把生僻字也当成了同样说得通的竞争者**:
   格(木各)/挌(扌各)/恪(忄各)像素上几乎一样(0.8496 vs 0.8472),
   但字频分得开 → 改成**给常用字先验加分并参与 margin 计算**。
   修完:圻→**格** ✓ 还原了。

「坉」仍然判不出来,因为站点重绘后的「略」像素**离「赂」更近**(0.1007 vs 0.1162),
**像素里没有答案**,只能靠语境("战X管理能力"→战略),本版未做 →
系统**保守不改**(留密文码位,不写错字)。

### 换题回归(新增,2026-10-21)

用户每换一套题就换一套加密字体。这条测试专门盯这件事:
**同一个标签里来回换字体(A→B→A→B)**,两套字体码位相同、画成不同的字
(旧映射泄漏的话答案会明确错掉)。

| 场景 | 结果 |
| --- | --- |
| 第 1 题(A) | ✔ |
| 换题 A→B | ✔ |
| 换题 B→A | ✔ |
| 连续换题 A→B→A→B | ✔ 3/3 |

**这条测试第一次跑就抓出两个真 bug**(见 ADR-0009):
① 预热与选区用了不同阈值 → 换题后"选中就立刻复制"必然缺字
② 站点重绘笔画更细 → 灰度距离偏向笔画少的字(「略」被认成「赂」)

### 根因(ADR-0010)要点

| 观测 | 数值 |
| --- | --- |
| 失败字在不在库里 | **都在**(参考库是 GBK 全集 21517 字) |
| 墨量比(站点 vs 参考) | **0.880**,25 个码位全在 0.80~0.91 → 系统性变细 |
| 宽比/高比、重心偏移 | 1.00/0.98、≈0px → 几何完全一致 |
| 病根 A | 像素距离偏爱"笔画少"的字 → 「略」输给「赂」 |
| 病根 B | 库里有只差一笔的孪生字(国/囯)→ margin 0.0100 → 被闸门挡 |

**教训**:通用不是多写几个用例,而是找到那个**可被度量解释的系统性差异**。
前面几次都在阈值和规则层面打转,真正根因是**度量的量纲错了**。

### 换题后的"映射就绪窗口"(2026-10-21 晚)

复现:同标签内换字体 → 立刻复制。

| 时刻 | 剪贴板 |
| --- | --- |
| 换题后立刻 | **原始密文**（"天地玄黄宇宙洪荒日月盈昃…"） |
| 换题后第 1 轮 | ✔ 正确（1956ms） |

**=> "换题就失败"的机制:不是识别不准,是新字体的映射还没建好。**
修:① 预热与选区统一阈值(之前预热 0.88 / 选区 0.8,预热那张表少几条)
② 给"带混淆字体的标签"单开快轮询(~200ms)→ 就绪时间 2.0s → **0.5s**

### 明文到底在不在浏览器里(实测)

穷举搜过:DOM / 所有属性 / `<script>` / 输入框值 / 注释 / `window` 全局 → **没有明文**。
同源接口响应里也是密文(`aria-label='A 企嵻嵽嵼选择'`)。
**=> 混淆是服务端做的,明文从没到过浏览器**;页面里"正确"的只有字体里的字形和屏幕像素,
而像素路径拿到的形状信息与字形路径完全相同 → 反推字形是唯一可行路径。

### 验收判定自身的坑(已修)

`tools/verify/verify-app-e2e.cjs` 原先用 Unicode 区段(U+3400–U+4DBF)猜"密文字",
而学习通真实密文字在 **U+62xx / U+66xx / U+78xx**(抲 U+62B2、抸 U+62B8、曳 U+66F3)
→ **完全落在那个区段之外 → 永远判定为 0 → 假通过**。
现改为按**页面里实际下发的映射表**判定(表里的键 = 被混淆的码位),
并追加"明文片段命中"作为独立交叉验证。

### 「第一次成功、后两次失败」的真根因(ADR-0015)

**现象**:用户报「第一次成功,后两次失败」,并怀疑「题目被写死过」。
**「写死」这个猜测是错的** —— 全仓核对**没有任何写死的字→字映射**。

在真实学习通测验页上逐层拆,查出**三处断点**(都不是"写死"):

| # | 断点 | 查到的证据 | 修法 |
| --- | --- | --- | --- |
| 1 | **判活查询依赖 System Events** | `lastError` = "Safari 未运行",而 Safari 明明开着 19 个标签;`poll.lastProbe` **全空**(一次都没成功读到过标签) | 改用 `application "Safari" is running`;问不到 ≠ 没运行;Safari 没开是中性状态 |

### 「两三次错一次」的根因与修复(ADR-0016)

**现象**:用户复测「效果比刚才好,但依然是两三次中间出现了一次错误」,
怀疑"需要的时间还是偏长"。

**先证伪"分析慢"**:在同一份真机字体夹具 + 同一份参考库上逐段量两个引擎 ——
Rust(release)**13.4ms / 23.0ms** vs Electron(JS)**157ms / 248ms**。
**Rust 快 12 倍,分析根本不是瓶颈。**
(顺带发现 ADR-0015 里"11 秒 → 2.5 秒"那两个数是 **debug 构建**量的,
debug 比 release 慢 **25 倍** —— 那个数从来不是用户等的东西。)

**真凶**:一次 Apple Events 往返 ≈110ms(每次新起 osascript 进程),
而 Tauri 的轮询是**一条串行通道**:判活(110ms) → 列全部标签(110ms)
→ 目标站点标签**每 2 轮**才处理一次 → 实际 **~1 秒**才看一眼目标标签。
Electron 有**独立的 200ms 快轮询**,Tauri 移植时压成了单通道。

**"两三次错一次"的来历**:目标标签每 2 轮才被看一眼 → 大约一半的切题时刻
落在"还没轮到"的那一轮 → **失败率天然 ≈50%**,是有周期的,不是随机故障。

**修复**:补一条同形状的快通道(名义间隔 200ms、只盯建出过映射的标签、不判活不列标签),
主通道让位但靠心跳兜底(快通道死了主通道自动接管),
同一标签用处理权锁互斥;顺带把 `FastGlyphMatcher` 改成全局只建一次
(原先每次 `check_tab` 都克隆 9.7MB 的库并重建索引,**36ms/次**)。

**A/B 实测**(同一台机器、同一个页面、同一个探针、同样的安装流程,
唯一差别 = 有没有快通道;测法 = 清空映射 + 撤掉选区触发重新上报,
再轮询题目那层 frame 的 mappings 从 0 变成 >0 的时刻):

| | 改之前 | 改之后 |
| --- | --- | --- |
| 映射下发耗时 | 1605 / 2379 / 2619 / 2173 ms | **87 / 403 / 532 / 258 / 563 / 396 / 409 / 390 / 420 / 397 ms** |
| 均值 | **≈2194ms** | **≈320ms**(快 6.9 倍) |
| 端到端复制 | 常常复制出密文 | 剪贴板**无残留密文字**(连续 6/6 次)⚠️ **这一行当时是假绿**,判定口径见下面 ADR-0017 那段 |

**回归测试**:`cargo test --lib` **16/16**(新增 4 条:快通道登记/摘除、
同一标签只允许一条通道处理、**快通道死了主通道要接管**、目标标签每两轮才进主通道)。

**新装的包的现场自检**:
`fastPoll: {"alive": true, "cipherTabs": 1, "heartbeats": 20, "intervalMs": 200}`。
(`intervalMs` 是**名义间隔**;真实周期看 `periodMs`、干活耗时看 `workMs` ——
这两个字段是 ADR-0017 才加的,在那之前**没人量过快通道的真实周期**。)

## 验收记录(2026-10-23 末)

### 「换题后第 1 次成功、第 2 次复制出密文」的根因与修复(ADR-0017)

**现象**:用户复测「换一题之后,第 1 次复制成功,第 2 次复制失败(复制出来是密文)」。

在**真实学习通作业页**上把整条链路量了一遍:题目在**第 4 层同源 iframe**,
题目文字用站点临时生成的混淆字体 `font-cxsecret`(base64 内嵌在页面里,18.7KB);
**换题 = 站点重新生成一份混淆字体** → 作用域指纹变了 → 必须重建映射。

**三处页面侧根因**(守卫 `packages/browser-adapters/shared/`,两个仓库共用):

| # | 根因 | 地面真相 | 修法 |
| --- | --- | --- | --- |
| 1 | 「送到了就不重报」**用错了账本** | 判据用 `mappings[scopeKey]`(回答的是"页面能不能修复复制"),不是"App 知不知道" → App 重启后页面仍留着上一任 App 的映射 → 页面以为"不用报" → App 永远学不到这个作用域 → 不登记快通道 → **快通道是瞎的** | 两本账分开:`mappings`(页面能不能修,resync **不动**)与 `deliveredAt`(App 知不知道,resync **清它**)。清 `mappings` 反而会制造"用户复制出密文"的窗口 |
| 2 | 预热扫描触发条件太窄 | 站点顺序是"先注入 @font-face → 再渲染题目文字" → 第一次扫描时签名**已经是新字体**但扫到 **0** 个作用域 → 之后签名不再变 → **永远不再重扫** → 新作用域永远发现不了 | 触发条件加上"DOM 变了":MutationObserver 只置 `domDirty` 标志位(不做扫描),扫描仍每轮最多一次(13ms/帧) |
| 3 | 字体指纹用**取样哈希** | 混淆字体是"结构相同、字形不同"地生成的 → 取样点可能落在两份字体**相同**的字节上 → **撞车** → 旧映射套新字体 → 复制出**错的字**(违反"宁可留错字,绝不写错字"那条底线) | 改成**整份哈希**(FNV-1a,18KB ≈0.1ms)。真机上同一份字体:取样 `datagi2tog` → 整份 `data2cozfw` |

> 另外顺带修掉一条**致盲**的规则:原来"报过但没收到映射 → 冷却 3 秒再试"。
> 报告可能半路丢掉(frame 被重建、报告被别的东西取走),而 App 一次都没收到 →
> 这 3 秒里 App 根本不知道这个作用域存在。**节流改靠 ack,不靠计时器**:
> 没被 ack 就每轮重报(App 侧有负缓存,重试很便宜)。
> 这条改动让 Electron 的 `iframe-case` 闭环用例**从红变绿**。

**两处 App 侧性能缺陷**(Tauri;不是根因,但直接吃掉了留给用户的余量):

1. `state_once` 那个 `OnceLock` **从来没 `set` 过** → `get()` 恒为 None → 计数恒 0
   → `0 % 5 == 0` 恒成立 → **每轮都强制重注入**(多一次 25KB Apple Event)。
2. 字体**解析**失败没有负缓存:icomoon 的 URL 返回 **529 字节的 HTML**
   (curl 退出码 0 → "下载失败负缓存"根本抓不到)→ **每轮白下载 130~160ms**。

**修完后的真机验收**(重建的 release 包 + 已安装的 App + 真实学习通作业页):

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| App 重启后能不能学到已有作用域 | **学不到**(快通道是瞎的) | ✅ **能**(resync:页面上报时刻前进 **22 秒**,`cipherTabs=1`) |
| 换一题后新作用域能不能被发现 | **发现不了**(守卫 `pageScopes=0`) | ✅ **能**(重载题目那层 → **1498ms** 后新作用域的映射已在页面里) |
| 换题后复制 | 复制出**密文** | ✅ **0/4 密文**,全是明文 |
| 连打 6 轮复制(不换题) | — | ✅ **0/6 密文**(参考明文口径) |
| 快通道周期 | **450ms**(工作 240ms) | ✅ **205ms**(工作 110ms) |
| 映射从零到页面(resync 口径) | — | 116 / 300 / 705ms(均值 ≈370ms) |

> 上一轮记的"6/6 无残留密文"其实是**假绿** —— 那会儿的探针拿"复制瞬间守卫手里的映射键"

## 验收记录(2026-10-23 末之后)

### 每轮重报与日志刷屏(ADR-0018)

**现象**:ADR-0017 修完之后在真机上复查,看到三件不对的事:

1. 页面**每 200ms 重报一遍作用域**,其中一半是永远建不出映射的普通字体;
2. **守卫日志被 'pending' 冲光** —— 200 条环形缓冲三十来秒就没了,
   真正要看的 `copy-repaired` / `copy-no-mapping` 被挤掉;
3. Electron 侧页面里的旧版守卫永远换不掉。

**根因**:节流改成「靠 ack」之后,**永远不会被 ack 的作用域**就变成了每轮都报。
普通字体作用域(作用域 key 结尾 `#nofont`)**永远建不出映射** → 永远等不到 ack。

**修法**:

| # | 改了什么 | 在哪 |
| --- | --- | --- |
| 1 | 页面侧**不上报**"没有字体来源"的作用域(普通字体) | 共用守卫 `page-guard.ts`(v9 → **v10**) |
| 2 | 'pending' 日志**内容没变就不重复记**(变了才记) | 同上 |
| 3 | 页面里的守卫**版本**对不上就立刻重新注入 | Electron `coordinator.js` + `bridge.js` |
| 4 | 「看住的标签」两张表的键**统一成一种写法** | Electron `coordinator.js`(`tabKey()`) |

> 过滤「普通字体」**不会漏报**:作用域 key 的指纹部分就带着字体来源
> (`#nofont` / `#<内容哈希>` / `#url<哈希>`),字体来源变了就是**另一个 key**。
> 取字体失败、解析失败这些「暂时失败」的**继续报** —— 宁可多报一次,
> 也不能漏掉一个「本来能还原、因为不报而没还原」的字。

**真机复验**(真实学习通作业页,题目在第 4 层同源 iframe;重装 v10 后现场升级):

| 项 | 修之前(v9) | 修之后(v10) |
| --- | --- | --- |
| 页面里每轮上报的作用域 | **2 个**(两个普通字体,`fonts:["none","none"]`) | **1 个**(混淆字体,`fonts:["data"]`) |
| 最近 13 秒里的 'pending' 条数 | **约 65 条** | **0 条** |
| 守卫日志 200 条里的构成 | 166 pending + 33 reinjected + 1 resync | 升级后只有 1 条 pending,其余全是 reinjected-skipped |
| 页面里的守卫版本 | v9(换包后一直不换) | **v10**(就地升级,`upgraded` + `installed`) |
| 复制(连打 6 轮) | — | **0/6 密文** |

升级那一刻的日志(真机原样):

```
#127 1792740493878 pending {"kind":"selection","groups":2,"chars":44,"fonts":["none","none"]}   ← v9
#128 1792740494018 upgraded                                                                 ← 装上 v10
#130 1792740494023 pending {"kind":"selection","groups":1,"chars":80,"fonts":["data"]}          ← v10
#131 1792740495082 reinjected-skipped   ← 之后全是它,再没有 pending
```

## 验收记录(2026-10-23 末之后 · 换页滑条 / 录制排除 / 单条删除)

这一轮是三条用户反馈(详见 `06-决策/ADR-0019`):

1. 换页时内容区**底下**那条滑动的横条去掉,画面「直接划过去」的横滑动画保留;
2. 录制时点击**软件内部**不算一次点击(尤其「结束」按钮);
3. 录到的点击可以**单条删除**(不必一次性清空)。

### 1. 滑条:渲染逐帧实测

用 puppeteer 渲染面板、在切页过程中逐帧量(不改用户桌面、不截用户的窗口):

| 时刻 | `clientWidth` | `scrollWidth` | 横向溢出 | 有层在横向移动 |
| --- | --- | --- | --- | --- |
| 静止 | 502 | 502 | 否 | 否 |
| 切页 0 帧 | 502 | 534~545 | **是** | 是 |
| 切页 1~2 帧 | 502 | 648~729 | **是** | 是 |
| 切完 | 502 | 502 | 否 | 否 |

根因:`overflowY: 'auto'` 会让 `overflow-x` 也被算成 `auto`(CSS 规范:
一个轴是 `auto` 时,另一个轴的 `visible` 按 `auto` 算)。
退场的那一页往右滑(`x: '50%'`)→ 横向溢出 → 内容区底部冒出一条横向滚动条,
滚块跟着画面移动 = 用户说的「滑条」。

修法:内容容器加 `overflow-x: hidden`。**画面横滑动画一点没变** ——
溢出到右边的部分本来就在可视区外(`scrollLeft` 一直是 0,看不见),
只是多了一条能把它滑出来的滚动条。

> **高度上限(`maxHeight: '65vh'`)不是这条滑条的原因**。
> 历史上 `c4612e5` 去掉过高度上限、`f9d3bbf`(界面层照搬 Electron)又搬了回来 ——
> 但这条滑条在「没有高度上限」的那段时间里**同样存在**。

### 2. 录制排除:根因是「排除矩形一直是废的」

真机运行自检(`diag.json`):

| 口径 | 值 |
| --- | --- |
| 前端自报 `window.screenX / outerWidth / outerHeight` | `0 / 0 / 0`(screenY=1080) |
| 原生侧排除矩形(窗口事件维护) | `[700, 111, 1220, 410]`(520x299) |
| 安装脚本**独立**量到的窗口 | `520 x 298` |

→ WKWebView 里那套值**不能用**:老实现传给原生的排除矩形是空的一条线,
一次点击都没排除过。Electron 侧的值是准的,但同样只是**一张快照**,
窗口一动(尤其 Tauri 窗口贴合内容、**向上长**)就过期。

修法:排除矩形改由**原生层**算,并在窗口每次移动/变高时刷新
(Tauri 监听窗口 `Moved`/`Resized`;Electron 监听 `move`/`resize`),前端不再传。

**真机自检**(两组对照;启动参数 `--diag-recording-exclusion`):

```json
{ "conclusive": true, "control": 1, "excluded": 0, "posted": true,
  "point": [704, 171], "rect": [700, 111, 1220, 409] }
```

- `control: 1` → 对照组成立(合成点击确实被监听到);
- `excluded: 0` → 排除矩形生效:**点自己界面上的按钮不会被记成一次点击**。

不带参数启动时 `recordingExcludeRect` 也是对的(窗口事件单独就能维护),
`recordingExclusionCheck` 为 `null`(自检不跑)—— 平时不会有合成点击。

### 3. 单条删除

- 每条点击旁边一个「×」;「清空」**保留**(它是全清,不是被替代)。
- 停止录制时**不再清空**原生列表(两边一致),「删一条」时两边同步删同一条。
- 顺带修:Tauri 的 `stop_recording` 原来返回 bool,界面按数组用 →
  Tauri 侧「录制已停止(返回 **0** 个点击)」永远显示 0;
  现在返回点击数组(与 Electron 一致)。

## 2026-10-23:按快捷键就崩(Tauri 修复)+ 回放自激死循环(T0,两边修复)

### 1. 按快捷键就崩 —— Carbon TIS 的主线程约束

- 定位:三份崩溃报告,`faultingThread = cnc-hotkey`、
  `EXC_BREAKPOINT/SIGTRAP`、栈底 `TSMGetInputSourceProperty` ← `processEventTapData`
  —— 一次比一次完全一致:
  - `…-145432.ips`(14:54,用户按快捷键)
  - `…-180820.ips`(18:08,用户按快捷键)
  - `…-182847.ips`(18:28,**专门构的「修复前」对照构建 + 自检复现**)
- 修法:Carbon TIS 调用统一编排到主线程 + 跑错线程的守卫;
  命中记录改成「先落一条,再让主线程异步回填输入源」。
- Electron 线**不用改**:它的 TIS 调用本来就在主进程的主线程上。

### 2. T0:回放自激死循环(把用户的机器搞到强制关机)

- 环路:自检发真 ⌃⇧A → App 自己界面接住 → 触发回放 →
  回放的合成点击落在**自己窗口**上 → 点中自己的「默认执行」→ 又一次回放 →
  无限自激 + 并行回放线程 ⇒ 疯狂敲键盘 ⇒ 机器卡死。
- 三处缺口全补:① 自检不再发系统级事件;② 回放排除自己窗口;
  ③ 回放重入保护(同一时刻最多一个)。
- 两边同口径:Electron 的闸抽成 `playback-guard.cjs`(可测),
  Tauri 侧是 `commands/play.rs` 里的 `PLAYING` + `native::in_exclude`。

### 6. CI 抓出的一条坏断言(2026-10-23)

第一次推上去,Tauri CI **红了** —— `落点在自己窗口的点击被丢掉` 挂在 CI 上:

```
assertion `left == right` failed: 窗口外的点击要真的去发(这里发不出去是没权限)
  left: 1     right: 0
```

根因:那条单测**直接调**了 `native::mouse_click`,并断言
「因为没有辅助功能权限 ⇒ 点击发不出去 ⇒ executed=0」。
本机成立(没权限),**CI runner 上不成立**(它有权限)⇒ 那里真的把点击发到了屏幕上,
断言也跟着环境漂。

修法:把"点击怎么发"做成**可注入**的(`run_clicks_with`),
单测传一个假的发送器 —— 零副作用、跨环境稳定。
这正是本 ADR 第一节那条规矩:**合成输入事件不能拿真实系统当试验场**,
自检不行,单测也不行。

### 7. Windows 线的取舍(2026-10-23)

- **Tauri 的 Windows 线只上闸 ①(重入保护)**,**不上窗口穿透**。
  原因:穿透走 tao/wry 的 `set_ignore_cursor_events`,一旦被引用,
  链接器会多拉进一个系统 DLL ⇒ Windows CI 上**测试进程根本起不来**
  (`0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`)⇒ **Windows 线的测试门禁失效**。
  重跑两次都复现(不是抖动)。加上"Windows 上没法真机验证"、
  "穿透只影响回放完整性、不影响安全底线",先只保底线。
- **Electron 的 Windows 线上了穿透**:`setIgnoreMouseEvents` 是 Electron
  自带实现,不引入新的系统 DLL 依赖 ⇒ CI 绿 ✔。
- 因此 Windows 上两条线的差异:Tauri 有重入保护(不会自激、不会卡死),
  Electron 另有穿透(回放更完整)。这个差异是**有意为之**,记在这里。

### 9. 快捷键「从来没被吞过」(2026-10-23)

- 回归:`cargo test --lib` **29/29**(原 26 + 新 3)。
  新增 3 条**纯函数**单测(修饰键齐 / 修饰键缺 / 别的键)——
  不构造 `CGEvent`、不碰系统 ⇒ CI 上稳定。
  变异自检:M1(不认 ⌘⇧)/M2(不检查修饰键)/M3(D 不匹配)
  各被对应用例抓住,还原后 29/29 复绿。
- **没做完的**:「⌃⇧A 基本无法触发」那一半**还没定位** ——
  `diag.json` 证明 tap 是活的、匹配正常(4 条真实 ⌃⇧D 命中,flags 含 Control+Shift),
  但**一条 ⌃⇧A 都没有**。`shortcut-hits.json` 就是为了**按一下就能查到卡在哪一步**。

### 10. 快捷键「容错太低 / 要顺序无关」(2026-10-23)

- 用户反馈(ADR-0022 修完吞键之后仍然存在):
  > 「它的容错太低了,非得三个同时一起按,才有这样的效果。有的时候他可能
  >  有一点误差,可能是个有顺序的你所以要都要考虑到呀」

- 根因:判定只看**主键 keydown 那一瞬间事件自带的 flags**,没跟踪修饰键状态。
  三个键几乎同时落下时,硬件扫描顺序可能让**主键事件先于**修饰键的
  `FlagsChanged` 到达 ⇒ 那一刻 flags 还是空的 ⇒ 匹配不上 ⇒
  **既不触发、又漏给前台**(用户看到"多打出一个 D")。
- 修法:
  - tap 的 mask 加 `FlagsChanged`,自己跟踪当前按住的修饰键;
  - 判定用「跟踪到的 ∪ 事件自带的」(`effective_modifiers`)
    —— 前者解决"按下有先后",后者覆盖"App 启动前就按着修饰键";
  - 修饰键**后补齐**时**回头认**已经按下的键(`find_pending_hotkey`)
    ⇒ "先按 A,再补 ⌃⇧"也能触发;
  - 加 **2 秒时间窗** ⇒ "按住 A 打字半分钟,后来按 ⌃⇧"不会被误触发;
  - 触发过就把该键从"正按着"里拿掉 ⇒ 修饰键再变一次不会重复触发。
- 回归:`cargo test --lib` **32/32**(原 29 + 新 3);
  新增 3 条**纯函数**单测(修饰键后补齐也能触发 / 太久的键不认 / 有效修饰键取并集);
  变异自检 M1(时间窗失效)/M2(不取事件自带的修饰键)/M3(回头认时无视当前修饰键)
  各被对应用例抓住,还原后 32/32 复绿。
- **诚实的边界**:
  - 修饰键补齐**之前**先按下的那一键**已经漏出去了**,追不回来
    (macOS 事件流是单向的)。**完全��漏的用法是"先按住 ⌃⇧ 再按 A"**。
  - **⌘⇧ 也会被认成快捷键**,会抢 Chrome/Safari 的「新建标签页」。
    界面文案写的是 `Control+Shift+A`,严格说该只认 ⌃⇧ —— 但收窄能力要单独授权,
    本轮**保持现状**,记在 ADR-0023 待拍板。
- **Electron 线同样没有顺序容错**(系统热键),本轮没动。

### 11. 快捷键改成 ⌃S / ⌃D + latch(2026-10-23)

- 用户要求(ADR-0024):
  > 「不要 shift 了,直接 ctrl 吧 …… 触发之后 Ctrl 加 D 整个按键就不再会继续影响它了,
  > 除非下一次重新按住 Ctrl,再点击相应的字母」
- 改了什么:
  - **键位**:⌃⇧A → **⌃S**、⌃⇧D → **⌃D**;判定**只认 Control**,
    **不认 Command**、**不要求 Shift**(带 Shift 照样触发);
  - **latch**(两个框架**同一份规则**):触发 ⇒ 锁;
    **Control 松开** ⇒ 解锁;Control **按下**不能无条件解锁
    (迟到的按下事件会解除 latch ⇒ 按住 Ctrl 连按会连着触发 ⇒ 回放乱点);
  - Tauri 侧:新 latch 状态机 `Latch`(纯函数);
    **tap 被系统禁用后重建时清掉跟踪状态和 latch**(防"漏掉一次松开 ⇒ 彻底失灵")。
- 回归:
  - `cargo test --lib` **37/37**(本轮 +1:`迟到的Control按下不解锁`);
    hotkey 相关 **11 条全是纯函数**(不构造 `CGEvent`、不碰系统 ⇒ CI 跨环境稳定);
  - **变异自检**(base 先绿 → 变体被抓住 → 还原复绿):
    | 变体 | 被哪条抓住 |
    | --- | --- |
    | M1:Control 按下时**不看 blocked**就武装 | `迟到的Control按下不解锁` |
    | M2:触发后**不记 blocked** | `迟到的Control按下不解锁` |
    | M3:Control 松开时**不清 blocked** | **没被抓住** —— 实测是**等价变体**(行为不变),不是用例漏洞 |
  - Electron 侧:`node --test tools/verify/verify-shortcut-latch.cjs` **4/4**
    (已挂进 CI 硬门禁)、原生模块编译通过、`watchControlKey` 冒烟返回 `true`。
- **诚实的边界**:
  - **Windows 线两边都没有 latch**(Electron 的 `win-input` 没有只读监听;
    Tauri 的 Windows 线走系统全局热键)—— 平台差异;
  - **`win` 分支本轮没动** ⇒ Windows 包仍是 ⌃⇧A / ⌃⇧D;
  - latch 依赖"Control 松开"这件事被看到 ⇒ Tauri 侧在 tap 重建时清状态做恢复;
  - Electron 若拿不到只读监听 ⇒ `latch=false` **如实降级**,不假装生效;
  - 锁着的时候按键**照样被吞掉**(不往前台漏),只是不执行动作;
  - 自检**不发任何系统级键盘/鼠标事件**(ADR-0021)—— 全是进程内纯函数单测。
