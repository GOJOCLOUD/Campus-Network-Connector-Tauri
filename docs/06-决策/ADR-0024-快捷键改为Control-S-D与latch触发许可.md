# ADR-0024:快捷键改成 ⌃S / ⌃⇧D,并加 latch(触发一次就被消费掉)

- 状态:已定(Tauri / macOS 已实现;Electron / macOS 已实现)
- 日期:2026-10-23
- 相关:ADR-0023(顺序无关)、ADR-0022(吞键)、ADR-0020(按快捷键就崩)、
  ADR-0013(界面层逐字照搬 Electron)、ADR-0021(自检不许发系统级事件)
- 同名决策在 Electron 仓库是 **ADR-0013**(那边的 ADR 编号只排到 0012)

## 更正记录(2026-10-25 改键位)

本 ADR 的**键位**在 2026-10-25 被用户改了一次(决策本身不变):

| 项 | 2026-10-23 | 2026-10-25(**现行**) |
| --- | --- | --- |
| 剪贴板直入 | **⌃D** | **⌃⇧D** |
| 默认执行 | ⌃S | ⌃S(**不变**) |
| 修饰键判定 | 只认 Control | 只认 Control;**⌃⇧D 必须带 Shift** |
| 三键的触发判定 | 顺序严格、时间窗很窄 | **2 秒窗口内按下过即算**,**顺序不限** |

**为什么改**(用户原话,2026-10-25):

1. 「你不要用ctrl+D了,直接ctrl+shift+D吧」+「MAc上也改成一模一样的」
   ⇒ 两条线、两个框架**统一**成 ⌃⇧D(⌃D 在别的软件里是「退出」那一族,撞车概率高)。
2. 「在一定时间内,三个按键只要同时按了就可以触发就行了,别搞了非常严格的顺序,
   或者说时间间隔特别短,这样太难触发了」
   ⇒ 判定放宽:**修饰键在 2 秒窗口内按下过就算数**,顺序不限、可以已经松开。

**实现要点**(两个框架规则一致,机制不同):

- macOS 靠事件 tap 的「回头认」窗口:修饰键**按下过**就算数
  (纯函数 `StickyModifiers`,窗口 2 秒,可单测,不碰系统);
- Windows 侧靠 `RegisterHotKey` 的**系统级注册** —— 它要求修饰键在按键瞬间按住,
  「先按 D 再补 ⌃⇧」在 Windows 上**做不到**(要支持只能上低级键盘钩子,风险另计)。

## 背景

用户在 ADR-0023 修完之后仍然不满意,原话:

> 「不行,这整个机制还是有问题,**不要 shift 了,直接 ctrl 吧**,只要按住 Ctrl
> 再加一个 D,它就可以成功触发,然后默认执行的 Ctrl+shift+a 呢,也就换成我看一下
> **ctrl+S** 吧,**两个框架版本的都要换**,注意是摁住 Ctrl 的条件下点击 D 就触发,
> 然后**触发之后 Ctrl 加 D 整个按键就不再会继续影响它了,除非下一次重新按住 Ctrl,
> 再点击相应的字母**」

这段话里是**两个独立的要求**:

1. **键位**:去掉 Shift,改成 **⌃S**(默认执行/回放)+ **⌃D**(剪贴板直输);
2. **latch**:触发一次之后,Control 还按着、字母再按也**不再触发也不再有影响**;
   **必须松开 Control 再重新按住**,才恢复。

> ⚠️ 原文写的是「⌃⇧A 换成 ⌃S」,所以**去掉的是 Shift**;
> **不是**把 ⌃⇧A 换成 ⌘S。界面文案一直是 `Control+…`,以它为准。

## 一、决定一:键位 = ⌃S / ⌃D,**只认 Control**

| 快捷键 | 动作 | 平台 |
| --- | --- | --- |
| **⌃S** | 「默认执行」= 回放选中的录制文件 | macOS / Windows |
| **⌃D** | 读剪贴板(或输入框里固定的那段文本)并逐字键入 | 只有 macOS |

判定规则(`match_hotkey_raw`):

- **只认 Control**;
- **不认 Command** —— ⌘S 是「保存」、⌘D 是「书签」,抢了就是抢系统的;
- **不要求 Shift,但也不排斥它** —— 多带一个 Shift 照样触发(容错)。

> **顺带解决了一个老问题**:ADR-0023 里记着「⌘⇧A 也会被认成快捷键,会抢
> Chrome/Safari 的『新建标签页』,但收窄能力要单独授权,所以本轮保持现状」。
> **只认 Control** 之后,⌘⇧A 压根不在候选里 ⇒ 那个待拍板项**自动消失**,
> 不需要单独授权。

## 二、决定二:latch —— 触发一次就被"消费掉"

### 规则(两个框架**一字不差**)

```
触发                ⇒ armed = false 且 blocked = true
Control 松开        ⇒ blocked = false、armed = true      (彻底解锁)
Control 按下        ⇒ 只有 blocked == false 时才 armed = true
```

### 为什么"松开"才能解锁,"按下"不行

用户要的是「**重新按住** Ctrl」才恢复 —— 光看"按下"这一下是不够的,
因为**迟到的按下事件会解除 latch**:

```
用户按住 Ctrl + 按 D(两键几乎同时落下)
        ↓
主键的 KeyDown 先到 ⇒ 触发 ⇒ armed=false、blocked=true
        ↓
修饰键的 FlagsChanged 随后才到 ⇒ "Control 按下"这一下
        ↓
若它能无条件解锁 ⇒ 锁白设了 ⇒ 按住 Ctrl 连按 D 会**连着触发**
        ↓
而「默认执行」是**回放** ⇒ 触发多次 = 往用户屏幕上乱点一串合成点击
```

这正是 ADR-0023 描述的乱序场景(硬件扫描顺序不保证修饰键先到)。
⇒ **`blocked` 只能由「Control 松开」来清。**

### 为什么不用"按住 Control 再按 D 就一直能触发"

`globalShortcut` / 键盘自动重复都会**连着回调**。用户按住 Ctrl 不放、
手滑连按几下 D ⇒ 回放连着跑几遍 ⇒ 屏幕上乱点。
⇒ latch 是必须的,不是锦上添花。

## 三、两边的机制(**机制可以不同,规则必须一样**)

| | Tauri(macOS) | Electron(macOS) |
| --- | --- | --- |
| **触发源** | 自建 **tap**(主动 tap) | `globalShortcut.register('Ctrl+S' / 'Ctrl+D')` |
| **按键会不会漏给前台** | 不会 —— 主动 tap 自己吞(`swallow`,ADR-0022) | 不会 —— **系统热键替你吞** |
| **要「辅助功能」权限吗** | 要(App 有) | **不要**(系统热键不需要) |
| **怎么知道 Control 松开了** | 同一个 tap 的 `FlagsChanged` | 另开一个 **ListenOnly 会话级 tap** |
| **latch 状态机在哪** | `commands/native/hotkey.rs` 的 `Latch`(纯函数) | `shortcut-latch.cjs`(纯函数) |

### 为什么 Electron 不改成自建 tap

主动 tap(能吞键)**需要「辅助功能」权限**;而 `globalShortcut` 由系统替你吞键
⇒ 既不漏按键、也不需要权限。

> 2026-10-24 更正:原文写「Electron 是 ad-hoc 签名 ⇒ 拿不到那个权限」。
> 签名与能不能拿到权限**没有因果关系**;那条说法已随「为保留授权而做的那套机制」一起作废。
⇒ Electron 用**系统热键 + 只读监听**的组合。

**ListenOnly 的会话级 tap 不需要辅助功能权限**(只读监听是例外),
所以 Electron 拿它来观察 Control 的按下/松开边沿是可行的 ——
本机实测 `watchControlKey` 返回 `true`(tap 建起来了)。

### Electron 拿不到只读监听时 ⇒ **如实降级**

`watchControlKey` 返回 false ⇒ `canLatch = false` ⇒ 打一条 warn,
**维持旧行为**(按住 Ctrl 连按会连着触发)。**不假装 latch 生效。**

> ADR-0013 约束的是**界面层**逐字照搬;机制不同有先例(ADR-0020 的 Carbon TIS)。

## 四、诚实的边界(平台差异)

### ① Windows 线**没有 latch**

- Electron 的 Windows 模块(`win-input`)里**没有**这个只读监听;
- Tauri 的 Windows 线走 `tauri-plugin-global-shortcut`(系统全局热键),
  同样拿不到 Control 的边沿。

⇒ **两边的 Windows 线本轮都没有 latch**,维持旧行为。
这是**平台差异**,不是遗漏 —— 记在这里。

### ② `win` 分支本轮**没动**

两条产品线的 Windows 包在各自的 `win` 分支上(与 `mac` 分支独立,
CI 也是按分支出包的)。本轮实现落在 **`mac` 分支**,
⇒ **Windows 包仍是 ⌃⇧A / ⌃⇧D,也没有 latch**。
是否同步本轮改动,需要单独一轮方案(见"待办")。

### ③ latch 依赖"Control 松开"这件事被看到

如果那次 `FlagsChanged` **丢了**(tap 被系统禁用后重建、或事件流异常),
latch 可能停在"锁着" ⇒ 快捷键看起来"彻底失灵"。
⇒ Tauri 侧在**重建 tap 时**把跟踪状态和 latch 一起清掉(见
`commands/native/hotkey.rs` 的重建分支),给一条恢复路径。

### ④ latch 挡的是**触发**,不是**吞键**

锁着的时候,匹配上的组合键**照样被吞掉**(不往前台漏),
只是**不执行动作**。这是用户要的「整个按键不再会继续影响它」。

## 六、教训

**latch 这类"手感",必须两边同一份规则。** 第一版实现里 Tauri 侧是
「Control **按下**才武装」、Electron 侧是「Control **松开**才武装」——
同一个功能、两套语义,用户会拿到两种手感。
⇒ 定规则时**先定规则,再各写各的适配**;规则写进 ADR,两边照抄。

**"事件回调谁先到"是不确定的。** 系统热键的回调和只读监听的回调、
硬件扫描的主键和修饰键 —— 谁的顺序都不保证。
⇒ 任何"靠事件解除的锁",都必须能扛住**迟到的那一个**。
