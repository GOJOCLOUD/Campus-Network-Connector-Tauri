# ADR-0017:换题后复制出密文 —— 三处页面侧根因 + 两处 App 侧性能缺陷

- 状态:已定
- 日期:2026-10-23(末)
- 相关:ADR-0016(下发延迟)、ADR-0015(真实站点三处断点)、ADR-0011(明文不在浏览器里与换题时间窗)、
  ADR-0002(映射按字体建)、ADR-0009(换题自动适配)

## 背景

用户复测(2026-10-23):

> 换一题之后,第 1 次复制成功,第 2 次复制失败(复制出来是密文)。

在**真实学习通作业页**上把整个链路量了一遍,地面真相是:

- 题目在**第 4 层同源 iframe** 里(`mooc-ans/work/doHomeWorkNew`);
- 题目的文字用站点临时生成的混淆字体(`font-cxsecret`,**base64 内嵌在页面里**,18.7KB);
- 换题 = 站点**重新生成一份混淆字体** → 作用域指纹变了 → 必须重建映射;
- 真机复现:重载题目那层(≈换一题)后,**守卫扫到 0 个作用域**,
  用户选中复制 → 剪贴板里是密文(`D媖媘媙权媚字奱妸媗IPDL`)。

这一条把"偶发"变成了"必然":**新题目的作用域根本没被发现**。

下面三处是页面侧(`packages/browser-adapters/shared/`,**两个仓库共用**)的根因,
两处是 App 侧(Tauri/Electron 各自一份)的性能缺陷。

---

## 一、根因 1:「送到了就不重报」用错了账本 → App 重启后学不到任何作用域

### 现象

守卫 v7 起有一条规则:**"App 已经把映射送达到这一层 → 就不再上报这个作用域"**,
用来把一轮从 330ms 压到 110ms(不重复下发)。

但"送到了"当时是拿 `state.mappings[scopeKey]` 是不是存在来判断的 ——
而 `mappings` 这本账回答的是**"页面能不能修复复制"**,不是**"App 知不知道这个作用域"**。

两者在正常运行期一致,**在 App 重启之后就不一致了**:

| | 页面手里的 `mappings` | App 手里知道的 |
| --- | --- | --- |
| 正常运行 | 有 | 有 |
| **App 重启后** | **有**(上一任 App 留下的) | **空** |

于是:App 重启 → 页面觉得"不用报" → **App 永远学不到这个作用域**
→ 不会把它登记进快通道 → **快通道是瞎的** → 换题后只能等主通道那一圈(~1.2 秒)
→ 用户"换题立刻复制"就复制出密文。

### 决定:两本账分开记

守卫状态里新增 `deliveredAt`(scopeKey → App 送达的时刻):

- `mappings` —— 页面能不能修复复制(复制时查表用)。**resync 不动它**。
- `deliveredAt` —— App 知不知道这个作用域(决定要不要重报)。**resync 清它**。

`__copyRepairSetMapping`(App 把映射下发回来)写 `deliveredAt`;
`shouldReportScope` 改成只看 `deliveredAt`。

配套:`__copyRepairResync()`(App 对每个标签喊一次"重报")**只清 `deliveredAt`**,
`mappings` 原样保留 —— 清掉它反而会制造一个"用户复制出密文"的窗口,比不 resync 更糟。

### 顺带修掉的:上报冷却会致盲

原来还有一条"报过但没收到映射 → 冷却 3 秒再试"。那个冷却是**致盲**的:
报告可能在路上丢掉(frame 被重建、报告被别的东西取走),
而 App 一次都没收到 → 这 3 秒里 App 根本不知道这个作用域存在,
用户复制就是密文,而 App 明明下一轮就能拿到。

**真正的节流靠 ack,不靠计时器**:App 一旦确认处理过,这一层就不再报;
没确认过就**每一轮都报**(App 侧的重试有负缓存,重试很便宜)。

> 这条改动让 Electron 的 `iframe-case` 闭环用例从红变绿 ——
> 那条用例里 App 第一次没收到报告(被测试自己取走了),3 秒冷却期内它学不到作用域。

### 顺带修掉的:升级会抹掉映射

守卫换版本时原来是**整个换新实例** → `mappings` 被清空 → 从那一刻起用户复制就是密文,
要等 App 重新下发才恢复。**升级本身制造了一个"复制出密文"的窗口**。

改成**就地升级**:`mappings` / `charScopes` 保留(同一个字体 → 同一个作用域 → 旧映射照样对),
只补齐新字段;`deliveredAt` 清空(新一任 App 手里是空的,必须重新学一遍)。

## 二、根因 2:预热扫描的触发条件太窄 → 题目文字后渲染,新作用域永远发现不了

### 现象

v7 起把"每轮全量扫一遍"(13ms/帧)改成"**只在 @font-face 签名变了时**才扫"。
站点的顺序是:

> **先注入新字体的 @font-face → 再把题目文字渲染出来**

也就是**字体规则比用到它的元素先到**。于是:

1. 守卫第一次扫描时,签名**已经是新字体的了**(规则先到)→ 这次扫到 0 个作用域(元素还没渲染);
2. 之后题目渲染出来了,但 **@font-face 规则没变** → 签名不再变 → **再也不会重扫**;
3. 新题目的作用域**一直没被发现** → 映射没下发 → 用户复制出密文。

真机证据:重载题目那层后守卫 `pageScopes=0`;**手动把签名清空再扫一次,立刻就发现了**
(作用域报上来、映射随后送达)。这正是本 ADR 修复的那一处。

### 决定:触发条件加上"DOM 变了"

守卫装一个 `MutationObserver`(只置一个标志位 `domDirty`,不做任何扫描):

```
needScan = 签名变了 || DOM 变了
```

扫描仍然是**每轮最多一次**(13ms/帧),只是触发条件多了一条。

> 为什么不用"每轮都扫":一页十个 frame 就是 130ms,占掉一整轮的一半时间。
> 为什么不用"元素个数变了":换题可能是一换一(个数不变),抓不到。

## 三、根因 3:字体指纹用取样哈希 → 新字体可能沿用旧作用域 → **写错字**

作用域 key 里带字体内容指纹(`font-cxsecret#<指纹>`),目的就是
"换字体 = 换作用域 = 重新映射",不让旧字体的映射套到新字体上。

原来的指纹是**取样哈希**(每 N 个字符取一个,理由是"base64 可能十几 KB")。
但站点的混淆字体正是**结构相同、只有字形不同**地生成的 ——
取样点完全可能落在两份字体**相同**的字节上 → **撞车**。

撞车的后果不是密文,是**错字**:新字体沿用旧作用域 → 页面以为 App 已知、不再上报
→ 旧映射继续套在新字体上 → 复制出来的是**错的字**。
这直接违反"**宁可留错字,绝不写错字**"那条底线。

### 决定:整份哈希

`fontFingerprint` 改成对字体来源**整份**做 FNV-1a(18KB 字符串约 0.1ms,
扫描时每个字体算一次)。实测:改之前真机上是 `datagi2tog`(取样),
改之后是 `data2cozfw`(整份)—— 同一份字体,两个值。

## 四、App 侧的两处性能缺陷(不是根因,但直接吃掉了留给用户的余量)

### 4.1 `state_once` 从没被 `set` 过 → **每轮都强制重注入**

Tauri 侧把"强制重注入"的计数从全局改成**按标签**时,那个 `OnceLock` 只写了
`OnceLock::new()`,**从来没有 `set`** → `get()` 永远是 `None` → 计数恒为 0
→ `0 % FORCE_INJECT_EVERY == 0` 恒成立 → **每轮都重注入一次**
(一次 25KB 脚本的 Apple Event ≈110ms)。

实测:快通道的**工作耗时 240ms、周期 450ms**;修好后 **工作 110ms、周期 205ms**。

> 顺带把快通道的 sleep 口径改成和 Electron 的 `setInterval(fastTick, 200)` 一致:
> **睡到下一轮的名义时刻**,而不是"干完再睡 200ms"。

### 4.2 字体**解析**失败没有负缓存 → 每轮白下载一次

站点的图标字体 URL 常常返回一个 **HTML 错误页**(实测学习通的
`icomoon.ttf?ca3c1w` 返回 **529 字节的 HTML**)。这种 URL **下载是"成功"的**
(curl 退出码 0、字节非空)→ "下载失败负缓存"根本抓不到它 →
**每轮都要重新下载一次(实测 130~160ms)+ 再解析一遍**。

现在解析失败也记负缓存(URL 级:连下载都省掉;内容哈希级:省掉解析),
冷却 10 分钟(沿用下载失败那档)。

## 五、实测(真机,真实学习通作业页,题目在第 4 层同源 iframe)

| 指标 | 改之前 | 改之后 |
| --- | --- | --- |
| App 重启后能不能学到已有作用域 | **学不到**(快通道是瞎的) | **能**(resync:页面上报时刻前进 22 秒,`cipherTabs=1`) |
| 换一题后新作用域能不能被发现 | **发现不了**(守卫扫到 0 个) | **能**(重载题目那层 → 1498ms 后新作用域的映射已在页面里) |
| 换题后复制 | 复制出**密文** | **0/4 密文**,全是明文 |
| 连打 6 轮复制(不换题) | — | **0/6 密文** |
| 快通道周期 | 450ms(工作 240ms) | **205ms**(工作 110ms) |
| 映射从零到页面(resync 口径) | — | 116 / 300 / 705ms(均值 ≈370ms) |

> 判定口径:**和参考明文比**。
> 早先的探针用"复制瞬间守卫手里的映射键"判断有没有残留密文字 ——
> **映射还没下发时那本账是空的 → 比对的 key 集也是空的 → 判成"没有残留"**,
> 于是"6/6 无残留密文"其实是假的(剪贴板里明明是密文)。这条坑记在用例注释里。

## 七、没做的(以及为什么)

- **守卫版本不匹配时立刻重注入**:现在靠"每 5 轮强制补一次"兜底(App 更新后几秒内换新)。
  要"App 一更新、页面立刻换新"需要把版本号带进协议,多一份状态同步,收益小,暂不做。
- **Electron 侧 `ticksSinceInject` 的计数从来没生效**:`watched` 的键是字符串,
  取的时候用的是数字键 → 永远取不到 → 强制重注入从不发生(靠"守卫不在才注入"兜底)。
  这是**既有**偏差,不在本次范围内,单独记一笔。
- **把"新字体的分析结果"缓存到磁盘**:分析只要 13ms(ADR-0016 实测),不值得。
- **`set_mapping` 合并多个作用域成一次 Apple Event**:同 ADR-0016,当前一页只有一个混淆作用域。
