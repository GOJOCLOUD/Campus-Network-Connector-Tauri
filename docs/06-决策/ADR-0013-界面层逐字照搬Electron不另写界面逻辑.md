# ADR-0013:界面层逐字照搬 Electron,不另写界面逻辑

- 状态:**已定**(用户 2026-10-22 明确指令)
- 日期:2026-10-22
- 相关:ADR-0012(平台功能范围)、`docs/00-概览/Electron-对照调研.md`
- 性质:**实现口径定稿**。界面层任何改动都要先对照本文件。

## 背景

用户在真机上用 Tauri 版时发现:

> 「electron 的版本打开是好的呀,根据不同的界面长度变化,它确实会拉伸。
> 现在我说的是新版本,新版本它根本就不会动……像横切一刀,你往下翻,他就直接从这里截断。」

查证后确认是**两个独立缺陷叠加**,都出在"搬界面"这件事上,不是换框架的必然:

### 一、窗口不跟随内容 —— 触发压根没挂上

`src/tauri-bridge.js` 是 `window.cnc` 的实现层,在 `src/main.jsx` 里 **import 时同步执行**
(`import './tauri-bridge.js'` 排在 `createRoot().render()` 之前)。那一刻 React 还没渲染,
`document.querySelector('.rounded-4xl')` 必然是 `null`,于是

```js
const card = document.querySelector('.rounded-4xl')
if (card) observer.observe(card)   // ← 永远不执行
```

**ResizeObserver 从未挂载**。窗口只在启动时那两次 `setTimeout(fitWindow, 60/400)` 里被动过,
之后换页窗口再也不动。

### 二、内容不压缩 → 超出部分被根容器一刀切掉

我一度把 Electron 原版内容区的 `maxHeight: '65vh'` 删掉了(理由写在当时的注释里:
"窗口会跟着内容长,再加个上限等于把功能藏进滚动条")。**这个理由是错的**:
窗口跟着长 ≠ 内容可以不压缩;内容不压缩 + 根容器 `overflow-hidden` = **超出部分不是滚动,
是被切掉,而且没有滚动条能翻到**。

真机 `diag.json` 当时的实况(停在第 3 页):

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `innerHeight` | 297 | 窗口停在第 2 页的高度,不再跟内容 |
| `cardRect` | h=378, y=40 | 卡片底边 = 418 |
| `ringBottom` | **-121** | 卡片底部 121px 在窗口外面 |
| `contentMetrics` | 172 / 172 | 内容区**没有滚动条**(172=172),所以"往下翻"翻不动 |

被切的是根容器的 `overflow-hidden`,不是内容区 —— 这正是"横切一刀"。

## 决策

### 一、界面层只做"逐字照搬",不另写

`tauri/src/**` 与 `electron/src/**` 的差异,**只允许**下面两类,其余必须逐字相同:

| 类别 | 具体 | 为什么允许 |
| --- | --- | --- |
| Tauri 必需 | `data-tauri-drag-region` 共 4 处(`App.jsx` 根容器 1 处 + `Stepper.jsx` 3 处) | Electron 靠 CSS `-webkit-app-region: drag`,WKWebView 不认;Tauri 只认这个属性 |
| Tauri 必需 | `main.jsx` 多一行 `import './tauri-bridge.js'` | 桥接层 |
| 已定产品差异 | 第 4 页「辅助功能」授权小问号 | 用户明确要求(小问号,不是大横幅) |
| 已定产品差异 | Windows 线显示「键盘输入」页 | ADR-0012:Windows 保留拼音自动键入 |

> **2026-10-24 更新**：「辅助功能」小问号这条差异**已经注销** ——
> Electron 版也补上了(`KeyboardPanel.jsx` 与 `App.jsx` 逐字对齐),
> 因为 Electron 版同样要发合成点击/按键,同样需要「辅助功能」权限,
> 少了它用户就不知道自己为什么"点了没反应"。
> 详见 Electron 仓库 **ADR-0015**。

**判定口径(以后每次改界面都先问这句):「Electron 那边对应的是什么?」**
答不上来 → 这段自写逻辑不许留。

### 二、窗口高度上限用 Electron 那一行,不许另发明

内容区封顶**逐字用** Electron 的 `maxHeight: '65vh'`(配 `overflowY: 'auto'`):
内容多了就在**中间滚动**,不把卡片撑出窗口。

窗口高度另有一条硬约束:**不许超过屏幕**(原生侧 `window_fit_to_content` 按显示器高度钳)。
超了屏幕,底边就跑到屏幕外 —— 那还是"被切",只是从窗口边挪到了屏幕边。

### 三、窗口贴合内容的触发必须真的挂上

量窗口的代码在 Tauri 侧是**必须存在**的(Electron 的窗口固定 520×640,不需要这一步),
但它的触发条件只能是"**卡片存在**":卡片出现就挂 observer,卡片被替换就重新挂。
**不允许**在桥接层安装时直接 querySelector 一次就算完事。

## 代价

- Tauri 的**窗口高度**和 Electron 不同:Electron 固定 640,Tauri 贴着内容(298~562)。
  这是用户明确要求的(「窗口不能只是变透明却仍占那么大」),**面板本身逐字一致**。
- 窗口高度的原生侧钳制依赖显示器尺寸,多屏切换时以当前窗口所在屏为准。
- 删掉 `maxHeight: '65vh'` 之后写下的那条注释(理由是错的)已经作废,不再保留误导性说法。
