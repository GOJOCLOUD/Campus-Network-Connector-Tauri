# ADR-0022:快捷键「从来没被吞过」—— core-graphics 的 `None` 是放行,不是丢弃

- 状态:已定(Tauri 线已修;Electron 线同类问题**未修**,见文末)
- 日期:2026-10-23
- 相关:ADR-0020(按快捷键就崩)、ADR-0021(回放自激死循环)

## 背景

2026-10-23 晚,用户报告:

> 「快捷键行为仍然不准确,甚至现在基本都无法触发,只能误差的打出了一个 D」

「多打出一个 D」是这条产品线**最早**的投诉之一,`commands/native/hotkey.rs`
的文件头注释里还留着当年的记录:

> 用户反馈(两个版本都有):「快捷键的模糊区间比较小,必须按的非常精准才能生效,
> 有时候很容易多打出一个 D 来」

为了根治它,Tauri 线放弃了系统的全局热键(`Carbon RegisterEventHotKey`),
改成**自己用事件监听(CGEventTap)实现** —— 注释里写着这样能"把按键吃掉 ⇒
别的应用收不到,绝不漏出 D"。

**但它从来没吞掉过。**

---

## 一、根因:`None` 是放行,不是丢弃

`commands/native/hotkey.rs` 的 tap 回调一直这么写:

```rust
// 返回 None = **吞掉这个按键** ⇒ 别的应用收不到,不会多打出 D
return None;
```

**这句注释是错的。** core-graphics 0.24 的 tap 回调实现
(`core-graphics-0.24.0/src/event.rs`):

```rust
let event = CGEvent::from_ptr(_event);
let new_event = (*callback)(_proxy, _etype, &event);
let event = match new_event {
    Some(new_event) => new_event,
    None => event,          // ← None = 原样交还 = 放行
};
ManuallyDrop::new(event).as_ptr()
```

`Option<CGEvent>` 的语义是:

| 返回值 | 含义 |
| --- | --- |
| `None` | **不改**,用原事件继续往下走 ⇒ **放行** |
| `Some(e)` | 用 `e` **替换**这个事件 |

**这个 API 没有"丢弃"这个选项。** 想让一个事件消失,只能把它的类型改成
`CGEventType::Null` 再交回去 —— 系统收到一个 null 事件,就当什么都没发生过。

于是这个 tap 一直是个**纯观察者**:每次 ⌃⇧A / ⌃⇧D,**整个组合都完整漏给了前台应用**。

### 为什么症状是"打出一个 D"

修饰键没被系统识别成完整的 ⌃⇧ 时(比如多带一个 Fn/⌥、或那次按压本身就有偏差),
前台应用收到的是 **⇧D** —— 一个**大写 D**,直接被打进输入框。

修好"吞掉"之后,匹配上的组合键的主键(keydown + keyup)都不会再漏出去,
这条投诉才真正被解决。

---

## 二、为什么一直没被发现

三个原因叠在一起,每一个单独都足以让它漏过去:

1. **注释当成事实。** 代码里写着"返回 None = 吞掉 ⇒ 不会多打出 D",
   后来接手的人(包括我)读注释就以为这事已经解决了,没人去核对
   **依赖库对这个 API 的真实语义**。
2. **"匹配到" ≠ "吞掉"。** 之前所有的自检(`--diag-hotkey-trigger`、
   `shortcuts.hits` 的记录)验的都是**匹配** —— tap 有没有认出这个组合键。
   认出 ⇒ 记一笔。**从没验过那个按键有没有真的被拦住**。
   两个是完全不同的能力,却共用了一个"看起来像已验证"的证据。
3. **症状被归因错了。** 「多打出一个 D」被当成"匹配太严"的问题,
   于是修法是"放宽匹配"(多带 Fn/⌘ 也认)—— 方向对了一半,但**没解决泄漏本身**。

---

## 三、修法

### ① 真的吞掉

`commands/native/hotkey.rs`:

```rust
fn swallow(event: &CGEvent) -> Option<CGEvent> {
    let mut dead = event.clone();
    dead.set_type(CGEventType::Null);
    Some(dead)
}
```

命中时返回 `swallow(event)` 而不是 `None`。

### ② 长按的自动重复也要吞

原来 autorepeat 分支是 `return None`(放行)—— 长按 ⌃⇧A 会一次次把 A 漏给前台。
现在一样吞掉。

### ③ 配套的 keyup 也要吞

否则前台应用会收到"没有 keydown 的 keyup"。这一条原来就写对了
(`pending_keyups`),只是它返回的也是 `None`(放行),等于没做。

### ④ 命中记录立刻落盘

命中记录原来**只存在内存里**,要等前端调 `diag_report` 才会落盘 ——
App 在后台、窗口没开的时候根本查不到。「按了快捷键没反应」就是这样查不出来的。

现在每次命中异步写 `shortcut-hits.json`(app 数据目录):

```json
{ "updatedAtMs": 1792759805309, "hits": [ { "key": "⌃⇧A", "outcome": "命中(按键已吞掉)", "flags": "0x60103", "inputSource": "ABC(ASCII)" } ] }
```

写文件丢给别的线程 —— **tap 回调里做慢活,系统会直接把 tap 关掉**
(快捷键间歇性失灵)。这是 ADR-0021 里那条纪律的延续。

## 四、回归

- `cargo test --lib`:**29/29**(原 26 + 新 3)
- 新增 3 条单测覆盖 `match_hotkey_raw` 的纯判定(修饰键齐 / 修饰键缺 / 别的键):
  - 拆成**纯函数**是为了让单测**不构造 CGEvent、不碰系统** ——
    CI 上没有「辅助功能」权限,构造事件源都可能失败,
    断言一旦依赖环境就会漂(ADR-0021 那次踩过)。
- 变异自检:
  | 变异 | 被哪条抓住 |
  | --- | --- |
  | M1:不再认 ⌘⇧ | `认得出两个快捷键` |
  | M2:完全不检查修饰键 | `少修饰键的不算快捷键` |
  | M3:D 不再匹配 | `认得出两个快捷键` |

  三条各自变红,还原后 29/29 复绿。

## 五、还没定位的那一半

**「⌃⇧A 基本无法触发」的原因,本轮没有定位。**

已知事实(`diag.json` 的 `shortcuts` 段,20:10 那次自检):

- `tap.alive = true`、`tap.error = ""` ⇒ **tap 是活的**
- `hits` 里有 **4 条真实按键命中**,`key` 全是 `⌃⇧D`,
  `flags = 0x60103`(含 `0x40000` Control + `0x20000` Shift)⇒ **匹配逻辑正常**
- 但**一条 ⌃⇧A 都没有**

所以"无法触发"既不是 tap 挂了、也不是匹配坏了。`trigger_default_execute` 里
每条分支都会记一条 hit(「开始回放 X」/「上一次回放还没结束」/
「X 里没有可执行的点击」/「一个录制文件都没有」),本轮加了 `shortcut-hits.json`
就是为了**按一下就能查到卡在哪一步**。

一个待查的疑点:用户的录制坐标是 `(1213,371)` / `(1208,405)`,
落在 App 窗口范围 `[1106,247,1626,545]` **之内**。
回放时如果窗口穿透失败,这些点击会被**跳过**(`skipped`)⇒ 看起来就是"按了没反应"。

## 六、影响范围

| 线 | 快捷键实现 | 本次状态 |
| --- | --- | --- |
| Tauri / macOS | 自建 `CGEventTap` | ✅ **已修**(ADR-0022) |
| Tauri / Windows | 系统全局热键 | 不适用(Windows 的热键由系统吞) |
| Electron / macOS | `globalShortcut.register`(系统热键) | ⚠️ **未修** |
| Electron / Windows | 系统全局热键 | 不适用 |

**Electron 线还有同一个毛病**:系统热键的修饰键必须**一模一样**,
对不上就不触发、而且按键**照漏**(用户当年的「多打出一个 D」两个版本都有)。
根治要改成自建 tap —— `mac-coregraphics` 原生模块里做,和 Tauri 这边同口径。
**本轮没做**,工作量不小,留作单独一轮。

## 七、教训

1. **注释不是证据。** 依赖库的 API 语义要去**读它的源码**确认,
   不能靠"注释说返回 None 就是吞掉"。
2. **"识别到"和"拦住"是两件事**,验了一个不等于验了另一个。
   证据要覆盖**被测能力的全部环节**。
3. **修一条数据流要把两头都走一遍** —— 和 ADR-0021 是同一个教训:
   上一轮改了回放那一头,没改快捷键这一头。
