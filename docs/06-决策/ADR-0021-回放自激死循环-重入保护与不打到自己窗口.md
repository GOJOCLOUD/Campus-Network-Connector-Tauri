# ADR-0021:回放自激死循环(T0)—— 重入保护 + 回放不得打到自己窗口

- 状态:已定
- 日期:2026-10-23
- 相关:ADR-0019(上一轮加的录制排除矩形)、ADR-0020(按快捷键就崩)

## 背景

2026-10-23 下午,做 ADR-0020 的真机自检时,用户报告:

> 「刚才我被迫关机了,因为你上一阶段完成的时候一直在软件里面点默认执行,
> 导致他反反复复一直尝试输入什么把整个电脑搞死机了,所以我被迫关机了,
> 这是个超级严重的 T0 级 Bug」

表现:App 反复在点自己的「默认执行」按钮、反复敲键盘,整台机器卡死,
用户被迫**强制关机**。

---

## 一、那条环路

```
① 自检往系统里 post 了一个**真的 ⌃⇧A**
        ↓
② App 自己的窗口接住了它(App.jsx 里也绑了 ⌃⇧A → defaultExecute)
        ↓
③ 触发「默认执行」→ 回放选中的录制文件
        ↓
④ 回放发出的**合成点击**落在 App 自己的窗口上
   (回放**没有**排除自己窗口 —— 上一轮的排除矩形只用在**录制**上)
        ↓
⑤ 点中自己界面上的「默认执行」按钮 → 又一次回放
        ↓
⑥ Rust 侧 spawn_playback **没有重入保护** ⇒ 并行起回放线程
        ↓
⑦ 每个回放线程都在敲键盘 ⇒ 机器卡死 ⇒ 强制关机
```

三个缺口,缺一不可:

| 缺口 | 后果 |
| --- | --- |
| ① 自检往系统里发真实按键 | 把用户的桌面变成了试验场 |
| ④ 回放不排除自己窗口 | 回放会点自己界面的按钮 |
| ⑥ 回放没有重入保护 | 一次触发能并行起成百上千个回放线程 |

**为什么 ④ 会出现**:上一轮(ADR-0019)加的「排除矩形」只接在**录制**那条路上
(`rec::set_exclude_rect` + 窗口事件刷新)。**回放**这条路是同一份数据的另一头,
当时没一起改。**修一处不等于修好一个数据流** —— 这是这次事故真正的教训。

**为什么 ⑥ 会出现**:前端的 `isExecuting` 看着像有保护,但 Rust 的
`play_file` 是 fire-and-forget(立刻返回"开始执行"),前端马上把 `isExecuting`
置回 false,保护形同虚设。

---

## 二、修法:两道闸 + 窗口穿透(两边同口径)

### 闸 ① 重入保护 —— 同一时刻最多一个回放

- **Tauri**(`commands/play.rs`):`static PLAYING: AtomicBool`。
  `spawn_playback` 先 `swap(true)`:拿不到坑就**直接拒绝**并记一次
  `rejected_count()`;回放线程结束时用 `Drop` guard 复位(哪怕线程 panic)。
- **Electron**(`playback-guard.cjs` + `main.js`):`createPlaybackGuard()`,
  同样 `tryStart()` / `finish()`,`finally` 里保证放开。
  闸抽成独立模块是为了**能进 CI 测**(main.js 要 Electron 运行时才起得来)。

这一道闸**直接切断无限循环**:不管多少触发源(界面按钮、全局快捷键、
界面里的 ⌃⇧A),最多一个回放线程。

### 闸 ② 回放不得打到自己窗口

- 回放每一步之前读一次**自己窗口的实时矩形**(就是录制那套,
  窗口一移动/变高就刷新的那个),落点在自己窗口里的点击**不发出去**,
  计入 `skipped`。
- 判定只有**一份**:`commands::native::in_exclude`(Tauri)/
  `playback-guard.cjs` 的 `pointInRect`(Electron),
  录制与回放共用 —— 写成两套迟早写出两套不一样的边界。

### 窗口穿透 —— 让点击落到**该去的地方**(正解)

闸 ② 是**兜底**,不是正解。真正的解法是**回放期间让窗口不接收鼠标事件**:

- App 的窗口是 always-on-top 的小面板,**常常正好盖在目标网站的输入框上面**
  (实测用户的录制文件里,两条要点击的位置就在 App 窗口范围内 ——
  那正是"点进输入框"的位置)。
- **不穿透** ⇒ 那个点击变成**点自己** ⇒ 点中自己的「默认执行」⇒ 又一次回放
  ⇒ 无限自激循环(用户看到的"疯狂输入",就是在反复键入学号/密码)。
- **只靠闸 ② 跳过**也不行 ⇒ 那些点击恰恰是**要点进输入框**的,
  跳过了回放就**点不进去**,密码输不进去 —— 那是另一种功能缺失。

所以回放开始时把窗口设成**穿透**,点击就正常落到下面的目标应用上:

| | API | 恢复时机 |
| --- | --- | --- |
| Tauri | `window.set_ignore_cursor_events(true)`(wry 在 macOS 上映射到 NSWindow 的 `ignoresMouseEvents`) | 回放结束时(`PlayingGuard` 的 `Drop`,panic 也恢复) |
| Electron | `mainWindow.setIgnoreMouseEvents(true, { forward: true })` | 回放结束时(`finally`) |

**穿透失败**(平台不支持/没权限)才退回闸 ② 跳过。

### 自检必须零副作用

- 自检**不再往系统里发任何键盘/鼠标事件**。
- 上一版自检(往系统 post 真的 ⌃⇧A)就是这次事故的直接原因,
  **已删除**。新的自检只在自己进程内走一遍那条会崩的代码路径:
  从非主线程读输入源 + 从非主线程记一次命中。
- 回放的两道闸也配了一个**零副作用**自检:造的落点**全在自己窗口内**,
  并且**先断言**这些落点确实会被丢掉 —— 断言不过就**直接返回错误、不起回放**,
  免得排除逻辑坏了还把点击发到用户屏幕上。

### Windows 侧的口径

- **闸 ①(重入保护)是跨平台的**(纯逻辑,不看平台)⇒ **Windows 上 T0 的底线也在**:
  回放点到自己的窗口 ⇒ 界面上再点一次「默认执行」⇒ 这次**被拒绝** ⇒ 最多误点一次,
  **不会自激、不会把机器搞死**。
- **闸 ②(排除自己窗口)目前只在 macOS 启用**。原因:排除矩形用
  Tauri 的 `outer_position/outer_size`(物理像素)换算成逻辑点,
  而 Windows 的 `SendInput` 用的是**虚拟屏幕绝对坐标**、量纲不一样,
  **坐标系没核实之前不能开** —— 开错了会把「不在窗口上的点击」当成
  「在窗口上」而丢掉,那是另一种功能缺失。
  等 Windows 线同步本轮改动时,先把坐标系核实清楚再开。
- **窗口穿透:Electron 的 Windows 线上了,Tauri 的 Windows 线**暂时没上**。
  - Electron 侧:`mainWindow.setIgnoreMouseEvents(true, {forward:true})` 是
    **Electron 自带的实现**,不引入新的系统 DLL 依赖 ⇒ Windows CI 绿 ✔
  - Tauri 侧:`window.set_ignore_cursor_events(true)` 走 tao/wry,
    **一旦被引用,链接器就会多拉进一个系统 DLL** ⇒ Windows CI 上
    **测试进程根本起不来**(`0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`),
    **Windows 线的测试门禁会直接失效**。加上"Windows 上没法真机验证"、
    "穿透只影响回放完整性、不影响安全底线"这两条,
    **先只上闸 ①(重入保护)那条底线**。
  - 等能在 Windows 上真机验证、且 CI 的测试进程能正常起来,再把穿透补回去。

## 四、留下的规矩

1. **合成输入事件是"往整个系统广播"** —— 拿用户的真实桌面当试验场
   就是在拿用户的东西做赌注。任何自检都**不许**发系统级键盘/鼠标事件;
   要验就用**假的发送器**或**先断言再动作**。
2. **单测也不能真的碰系统** —— 同一条规矩对单测一样成立。
   2026-10-23 CI 抓到过一次:那条"落点在自己窗口的点击被丢掉"的单测
   直接调了 `native::mouse_click`,并断言"因为没权限所以发不出去(executed=0)"。
   在**有**辅助功能权限的机器上(CI runner 就是)它会**真的点到屏幕**,
   而且断言也跟着环境漂(本机绿、CI 红)。
   修法:把"点击怎么发"做成**可注入**的(`run_clicks_with`),
   单测传一个假的发送器 —— 零副作用、跨环境稳定。
   **教训**:断言里出现"因为没权限所以…"这种**依赖环境**的假设,就是定时炸弹。
3. **任何"自己触发自己"的路径都要有重入保护** —— 不管触发源是
   界面按钮、全局快捷键,还是界面里的快捷键绑定。
4. **修一条数据流要顺着两头走** —— 排除矩形这种"同一份数据的两端",
   上一轮只接了录制那一头,回放这一头漏了,就成了 T0。
5. **T0 级的改动不能靠手测** —— 手测一次就要重启一次机器。
   必须有能进 CI 的回归(Rust 单测 / node --test)。
