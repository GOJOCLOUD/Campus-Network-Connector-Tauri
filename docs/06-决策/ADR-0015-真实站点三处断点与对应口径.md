# ADR-0015:真实站点上的三处断点(判活查询、frame 名单、字体分析)

- 状态:已定
- 日期:2026-10-23
- 相关:ADR-0014(注入脚本的字面量必须按 JSON 编码)、ADR-0004(按站点 URL 覆盖标签)

## 背景

ADR-0014 修掉了"守卫一次都没装上"。2026-10-23 用户在**真实学习通测验页**上复测,
报告:**第一次成功,后两次失败**,并怀疑"题目被写死过"。

这一轮在真机上逐层拆,查出**另外三处断点**。三条都不是"写死",而是链路上的环节断了:

1. **判活查询依赖 System Events** → 整个功能静默停掉;
2. **iframe 桥的 frame 名单过期** → 映射发不到真正有题目的那层;
3. **新字体的首次分析要 11 秒** → 这期间复制必然是密文。

用户"第一次成功"的真实原因:第一份字体的**分析结果被缓存**了,
换到新字体(新的 data URI)就是缓存不命中,又要等一遍分析。
**与"写死"无关** —— 代码里没有任何写死的字→字映射(已全仓核对)。

## 三处断点与决定

### 一、判活查询不许问 System Events

Electron 版用 `tell application "System Events" to (name of processes) contains "Safari"`
判断 Safari 在不在跑。Tauri 版照搬了这个写法 —— **问题就在这里**:

System Events 的进程列表需要**另一份**自动化授权("自动化 → System Events"),
**用户从来没被提示过这份授权**(界面上只提 Safari)。查询拿不到结果,
而老口径把"问不到"当成"没运行" → **整个功能静默停掉**:

| 症状 | 实际 |
| --- | --- |
| 界面显示"已开启" | 开关确实是开的 |
| `lastError` = "Safari 未运行" | 而 Safari 明明开着 19 个标签 |
| `poll.lastProbe` **全空** | **一次都没成功读到过标签** |
| 页面里守卫在、映射也在(昨天那次留下的) | 所以"第一次复制居然成功了" |

**决定**:

1. 改用 `application "Safari" is running` —— **不需要任何额外授权**(AppleScript 自己查进程表),
   也**不会把 Safari 拉起来**(问 Safari 自己才会启动它;`is running` 只查状态)。
2. **问不到 ≠ 没运行**:查询失败时按"在跑"处理(与 Electron 版同口径),
   真正的错误由紧随其后的 `list_tabs` 报出来(那里才有 -1743 这种准确原因)。
3. **Safari 没开是中性状态,不是错误**:清掉 `lastError`、把 `injected` 归零,
   界面走 `safariRunning === false` 那条灰色提示(与 Electron 版同口径)。

> ⚠️ 这条**只在 Tauri 线生效**:Electron 版仍问 System Events。
> 差异原因写在这里:那条路要一份用户从没被授予过的授权。

### 二、iframe 桥的 frame 名单必须**在使用前**刷新

真实测验页的题目在**第 4 层同源 iframe** 里。映射要发到那一层,
靠的是 bridge 里的 `framesInjected` 名单。

站点(SPA)在**嵌套 frame 内部**换 iframe(换题、翻页、加载下一段),
而 bridge 的 MutationObserver 只挂在**顶层文档**上 —— **看不见嵌套里的变化**
→ 名单一旦过期:

- 映射被发到上一套 iframe(浏览器上已经变成 `about:blank` 的那些);
- **真正在显示题目的那层一份映射都收不到** → 复制出来还是密文
  (守卫日志是 `copy-no-mapping`)。

真机证据:

- bridge 名单里 **17** 个 frame,而当前页面树只有 **10** 个(8 个是过期残留);
- 手动 `rescan()` + 分发一次 → 题目那层立刻拿到映射 → 复制出来是明文。

**决定**:

1. `take()`(收集)与 `setMapping()`(分发)**开头都先 `scan()`** —— 用之前先刷新名单。
2. `scan()` 把**当前树**里没有的旧 frame 从名单里剔掉
   (否则映射白发给一堆 `about:blank`,名单还越攒越多)。
3. `debug()` 的 pending 取值形状修正:是 `{ groups: [...] }`,不是 `{ chars: [...] }`
   —— 早先写错导致"一有 pending 就抛异常",**诊断工具自己坏掉**,排查时被它带偏过。

### 三、字体分析要并行

一份混淆字体有上百个码位,每个都要:栅格化 → 与参考库比对 → 取最近邻。
**串行实测 11 秒**(2026-10-23,真实站点那份 `font-cxsecret`)。

这 11 秒里页面上**一份映射都没有** → 用户"换题后立刻复制"必然复制出密文。

**决定**:逐码位的判定用 rayon 并行(各码位互不依赖、谁也不看顺序,
**判定口径一个字都没改**)。实测 11 秒 → **2.5 秒**(本机 10 核)。

**没有**为了更快而放松"字体级闸门"(那个闸门是"宁可留错字,绝不写错字"的底线):
分析仍然按**整份字体**做,闸门仍然按字体码位数为分母。

## 代价

- `scan()` 每次收集/分发都要走一遍 frame 树(实测 23ms,可接受)。
- 判活查询换掉了 → **与 Electron 版不再逐字相同**(理由见上)。
- 字体分析并行 → 峰值 CPU 占用上升(分析那 2.5 秒会用满多核)。

## 验证

- **真机(真实学习通测验页,题目在第 4 层同源 iframe)**:
  - 修复前:题目那层 `top>1>1>1` 的映射数 = 0,复制出来是密文;
  - 修复后:10 层 frame 全部拿到映射(33 个字),守卫日志 `copy-repaired`,
    剪贴板 = `【判断题】对技术系统进行分析时,着重分析其主要功能,辅助功能则可以被分离在技术系统之外。()`
    (修复前是 `【判断题】对技术系统进囆嚾囇时,囄重嚾囇囅主要功能,…`)
- **换题窗口**:清空映射后立刻复制 → 340ms 那次仍是密文,**2065ms 时已是明文**。
- **回归测试**(`tools/verify/verify-frame-bridge.cjs`):纯 node 造一棵假 frame 树,
  模拟"站点换掉 iframe"这个动作,断言**新那层必须收到映射**。
  同一套用例跑**两遍**:**入库产物**(真正装进 App 的那份)与**源码现编**(真身)——
  产物是手工从 `vendor/` 复制过去的,没有任何东西保证它们同步,两头都测才堵得住。
  实测:**把修复前的版本分别塞回去,各自那 3 个用例红 2 个**(产物旧 → 产物侧红;
  源码旧 → 源码侧红),换回新的 → 6/6 全过。
- `cargo test --lib` 12/12(含新增的"判活查询不许用 System Events"一条)。

## 同步到 Electron 版

`frame-bridge` 是两个仓库共用的同一份源码(TS 源逐字相同,产物也逐字相同),
所以这条修复**必须两边都改**:Tauri 仓库改 `packages/browser-adapters/shared/src/frame-bridge.ts`
并重新构建 `tauri-app/src-tauri/resources/frame-bridge.js`;
Electron 仓库改同名 TS 源(vendor/ 是构建产物,打包时重新生成)。
两边的提交说明都写清了"这是从另一条线搬过来的同一个修复"。

**两边都补了回归测试,也都接进了 CI 门禁**(跑不过就不发包):

| 仓库 | 测试读的是什么 | 为什么 |
| --- | --- | --- |
| Tauri | **入库产物 + 源码现编**,各跑一遍 | 产物是要装进 App 的那份,源码是真身;两者靠手工复制同步,必须都测 |
| Electron | **源码现编**(esbuild 现场编译) | vendor/ 是不入库的构建产物,读它等于测"上次构建留下的东西" —— 那是假通过 |

> ⚠️ **Electron 那一侧尚未做真机复验**:2026-10-23 的真机验证是在 **Tauri 版**上做的。
> 两个仓库的 `frame-bridge.ts` 逐字相同(已用 sha 核对),但**不能因此声称 Electron 版
> 也已在真机上验过** —— 要验还得单独在 Electron 版上跑一遍。
