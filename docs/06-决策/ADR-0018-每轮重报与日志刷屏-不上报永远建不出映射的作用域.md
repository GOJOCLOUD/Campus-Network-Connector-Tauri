# ADR-0018:每轮重报与日志刷屏 —— 不上报「永远建不出映射」的作用域 + 日志去重 + 版本比对

- 状态:已定
- 日期:2026-10-23(末之后)
- 相关:ADR-0017(换题后复制出密文)、ADR-0016(下发延迟)、ADR-0013(界面层照搬 Electron)

## 背景

ADR-0017 修完「换题后第 2 次复制出密文」之后,在真机上复查时又看到三件不对的事:

1. **页面每 200ms 重报一遍作用域**,而其中一半是**永远建不出映射**的普通字体;
2. **守卫日志被 'pending' 冲光**:200 条的环形缓冲三十来秒就没了,
   真正要看的 `copy-repaired` / `copy-no-mapping` 被挤掉 ——
   排查时连「这次复制走了哪条路径」都查不到;
3. **Electron 侧页面里的旧版守卫永远换不掉**。

三件事有同一个根子:**节流改成「靠 ack」之后,"永远不会被 ack 的作用域"就变成了每轮都报。**

ADR-0017 废掉了「报过但没收到映射 → 冷却 3 秒再试」那条规则(它会致盲),
节流改由 App 的 ack 承担。但 ack 只会落在**真建出映射**的作用域上,
于是**永远建不出映射**的作用域就变成了每轮都报、App 每轮都白处理一遍。

## 一、普通字体作用域:永远建不出映射,就别报

页面上大部分文字用的是**普通字体**(题干周围的正文、选项、说明)。
这类作用域的 key 结尾是 `#nofont` —— **没有字体文件**,App 侧永远建不出映射。

> 作用域 key 的结构:`normal|400|<字体族>#<指纹>`,
> 指纹部分就带着字体来源:
> - `#nofont` —— 没有 @font-face(系统字体)
> - `#<内容哈希>` —— data: 内嵌的字体
> - `#url<哈希>` —— 需要下载的字体

**会不会漏报?不会。** 字体来源变了就是**另一个作用域 key**
(`...#nofont` ↔ `...#<哈希>`),照样会上报。
所以过滤「没有字体来源的作用域」**只影响"永远不可能有映射"的那一批**,
不会把任何"将来可能有映射"的作用域挡在外面。

### 和「暂时失败」的区别(别混在一起)

| 情况 | 会不会有映射 | 该不该继续报 |
| --- | --- | --- |
| **普通字体**(没有字体来源) | **永远不会** | **不该报** → 过滤掉 |
| 取字体失败(404 / 跨源) | 可能会(站点修好了就有) | 该报 → App 侧有负缓存,重试很便宜 |
| 解析失败(拿到的是 HTML 错误页) | 可能会 | 该报 → 同上,负缓存 10 分钟 |
| 映射建成了 | 已经有了 | 不该报 → App 已 ack |

**只有第一类被过滤。** 后三类继续每轮重报 —— 宁可多报一次,也不能漏掉一个
「本来能还原、因为不报而没还原」的字。

## 二、日志:内容没变就不重复记

'pending' 是**每轮**都会发生的事(App 还没确认过 → 每轮重报)。
以前每轮都往日志里塞一条 → 200 条的环形缓冲三十来秒就被冲光,
`copy-repaired` / `copy-no-mapping` 这些真正要看的记录被挤没了。

改成:**上报内容的指纹没变就不记,变了才记一条**。
上报内容变了(换了作用域、多了少了字)照样能看出来。

> 这条不是"少记点日志好看",是**排查能力**:
> 真机复查时就是因为复制记录被挤掉,才查不出「这次复制到底走了哪条路径」。

## 三、版本比对:页面里的守卫旧了就重新注入

守卫自己会按版本号**就地升级**(保留 mappings、清 deliveredAt、强制重扫),
但前提是**有人重新注入它**。

- **Tauri 线**:每 5 轮强制重注入一次 → 版本一变就升级 ✓(本来就是这个口径)
- **Electron 线**:以前只在「守卫不在」时注入 → **旧版守卫能一直赖着**

Electron 侧还查出一处**既有的键不一致**(ADR-0017 记过一笔"ticksSinceInject 从来没生效"):

| 位置 | 键的写法 |
| --- | --- |
| `watchTab()` 存进去 | `w{windowIndex}t{tabIndex}` / `String(index)` / `'front'` |
| `restoreWatched()` 存进去 | `String(index)` |
| `processTab()` **读出来** | **裸数字的 `tabIndex`** |

存进去的和取出来的**不是同一把钥匙** → 永远取不到 → 计数永远从 1 开始 →
**强制重注入从不发生**。现在统一成一个 `tabKey()`。

再补一条:页面里的守卫**版本**对不上时**立刻重新注入**,不等「每几轮补一次」。

> 注意:这条**不是**把周期性重注入删掉。
> 周期性重注入还兼着一个重要职责:**站点新建 iframe 时给新 frame 装守卫**
> (新 frame 没有守卫 → 不重注入就收不到映射 → 那层复制出密文)。
> 版本比对只是**多一个**触发口子。

## 四、实测(真机,真实学习通作业页,题目在第 4 层同源 iframe)

| | 修之前(v9) | 修之后(v10) |
| --- | --- | --- |
| 页面里每轮上报的作用域 | **2 个**(两个普通字体,`fonts:["none","none"]`) | **1 个**(混淆字体,`fonts:["data"]`) |
| 最近 13 秒里的 'pending' 条数 | **约 65 条** | **0 条** |
| 守卫日志 200 条里的构成 | 166 条 pending + 33 条 reinjected + 1 条 resync | 升级后只有 1 条 pending,其余全是 reinjected-skipped |
| 复制(连打 6 轮) | — | **0/6 密文** |


## 五、回归测试(+4)

`tools/verify/verify-page-guard.cjs`(Tauri **32/32**、Electron **28/28**):

- `普通字体(没有字体来源)的作用域不上报(它永远建不出映射)`
  —— 并且带一条**对照**:选区落在混淆字体元素里时必须照常上报
  (别把过滤做成"什么都不报")
- `内容没变的 pending 不重复记日志(环形缓冲要留给真正要看的记录)`
  —— 连打 50 轮,'pending' 条数不许涨;上报内容变了必须再记一条

`src/features/safari-repair/test/watch-key.cjs`(Electron 专有,**4/4**):

- `看住的标签:键一致 → 强制重注入的计数能累加(到点就重新注入)`
- `页面里的守卫版本旧了 → 立刻重新注入(不等轮数到点)`
- `页面里的守卫版本是最新的 → 不注入`
- `守卫不在 → 照常注入`

**变异自检**(证明新用例真的抓得住,不是凑数):

| 变异 | 预期 | 实测 |
| --- | --- | --- |
| 去掉「普通字体不上报」的过滤 | 红 | 红 2 条(入库产物 + 源码现编)✓ |
| 去掉 pending 日志的去重 | 红 | 红 2 条 ✓ |
| 把「看住的标签」的键改回裸数字 | 红 | 红 1 条 ✓ |
| 去掉「版本对不上就重新注入」 | 红 | 红 1 条 ✓ |

## 六、没做的(以及为什么)

- **给「确定不需要映射」的作用域发一个负 ack**(App 侧新增一个协议调用):
  现在是**页面侧**直接不上报,效果一样、协议不用动。
  代价:App 的 `mappingScopes` 诊断里**不再出现**"普通字体,不需要映射"这几条
  (它们还在 —— 只是不再每轮被刷新)。
- **给守卫日志加分级**(info / debug):现在只做了"内容不变不重复记",
  够解决"复制记录被挤掉"这个问题。
- **把 `reinjected-skipped` 也去掉**:它每 1.1 秒一条,是无害的噪声,
  但它能证明"App 的周期性重注入在工作",留着有价值。
