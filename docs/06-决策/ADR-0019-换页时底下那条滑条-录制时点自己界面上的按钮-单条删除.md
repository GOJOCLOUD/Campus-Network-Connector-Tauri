# ADR-0019:换页时底下那条滑条、录制时点自己界面上的按钮、单条删除

- 状态:已定
- 日期:2026-10-23(末之后)
- 相关:ADR-0013(界面层逐字照搬 Electron)、ADR-0012(平台功能范围)

## 背景

这一轮是三条用户反馈,分属两个功能面:

1. **界面**:从第 1 页切到 2/3/4(以及切回来)时,内容区**底下**有一条横条在「滑动」;
   用户要求:去掉这条滑条,画面「直接划过去」的横向动画留着。
   用户还提到「这个之前改掉了,后面你又改回来了,这是一个失误」。
2. **录制**:录制时点击**软件内部**应该不算一次点击 —— 尤其点「结束」按钮。
3. **录制**:录到的点击必须能**单条删除**,不能只有一次性清空。

三件事都要**两条线同口径**(Tauri / Electron 是同一个产品的两个正式版本),
所以界面层逐字照搬,原生层两边各写各的但行为一致。

---

## 一、底下那条滑条:是**横向滚动条**,不是步骤进度线

### 1.1 定位

用 puppeteer 把面板渲染出来、在切页过程中逐帧量(不改用户桌面、不截用户的窗口):

| 时刻 | 内容容器 `clientWidth` | `scrollWidth` | 有横向溢出 |
| --- | --- | --- | --- |
| 静止 | 502 | 502 | 否 |
| 切页第 0 帧 | 502 | 534~545 | **是** |
| 切页第 1~2 帧 | 502 | 648~729 | **是** |
| 切完 | 502 | 502 | 否 |

同时能看到:切页时有一层在横向位移(`matrix(1,0,0,1,x,0)`),
x 从 -100% 走到 0%(进场),退场那层从 0% 走到 +50%。

### 1.2 根因

内容容器的样式是:

```jsx
style={{ position: 'relative', overflowY: 'auto', maxHeight: '65vh' }}
```

**按 CSS 规范,一个轴是 `auto` 时,另一个轴的 `visible` 会被算成 `auto`。**
所以 `overflow-y: auto` 实际上让**横向也能滚**了。

而切页时正在退场的那一页会往右滑(`x: '50%'`),横向就溢出了 ——
内容区**底下**于是冒出一条横向滚动条,滚块跟着画面一起移动 = 用户说的「滑条」。
macOS 上滚动条是 overlay 的,平时藏起来,**横向溢出的一瞬间它淡入**,于是被看见。

> 顶上步骤圈之间那条紫色进度线也会「动」(切换时填充 0→100%),
> 但它在**上面**,而且那是进度指示器,不是滚动条。用户说的是「下面」。

### 1.3 修法

内容容器加 `overflow-x: hidden`(横向不许滚),`overflow-y: auto` 保持不变
(长内容还得能滚)。

**画面「直接划过去」的动画一点没变** —— 理由是横向溢出到右边的那部分
**本来就在可视区外**(`scrollLeft` 一直是 0,看不见),
只是多了一条能把它滑出来的滚动条。改成 hidden 之后,
退场那一页依旧从右边滑出去、依旧淡出,只是不再有滚动条可滑。

### 1.4 「之前改掉了,后面又改回来」这件事

查历史:`c4612e5` 曾去掉过写死的高度上限(去掉 `maxHeight`),
随后 `f9d3bbf`(界面层逐字照搬 Electron)把 Electron 那份
`maxHeight: '65vh'` 搬了回来 —— **高度上限确实被改回来过**。

但**高度上限不是这条滑条的原因**:滑条来自 `overflow` 的轴向规则,
两边的写法一模一样。也就是说:用户看到的这条滑条,
在「去掉高度上限」那段时间里**同样存在**(那时候 `overflow-y: auto` 也在)。

结论写清楚,免得下次又当成「高度上限的问题」去改:
**要治的是横向溢出,不是高度上限。**

### 1.5 回归

新增 `tools/verify/verify-panel-transition.cjs`(两边逐字相同):

- 内容容器的计算样式必须是 `overflow-x: hidden` / `overflow-y: auto`;
- 切页过程中**必须**同时出现「有层在横向移动」(动画没丢)和「有横向溢出」
  (证明动画真在跑,这条用例不是恒绿);
- 把 `overflow-x` 在运行时改回 `auto` 复测一次,证明「同样的溢出在 auto 下
  就会冒出滚动条」—— 这条断言是**有判别力**的。

变异自检:把 `overflow-x: hidden` 去掉 → 用例转红
(`内容容器横向必须是 hidden,实际 auto`)。

> 为什么不用「量滚动条占位」的办法:macOS(以及 headless Chrome)上滚动条是
> overlay 的,**不占地方**,横竖都量到 0px,换任何 flag 都一样(实测)。
> 所以按规范判定,并用「溢出确实发生了」来保证这条用例有内容。

## 二、录制时点自己界面上的按钮:排除矩形一直是**废的**

### 2.1 老做法

前端在开始录制时算一个矩形交给原生:

```js
const left = window.screenX, top = window.screenY
const excludeRect = [left, top, left + window.outerWidth, top + window.outerHeight]
cnc.startRecording(excludeRect)
```

原生层把落在那个矩形里的点击丢掉。

### 2.2 实测:这个矩形在 Tauri 侧是**退化的**

真机自检(`diag.json` 里的 `windowRect`):

```json
"windowRect": { "screenX": 0, "screenY": 1080, "outerWidth": 0, "outerHeight": 0 }
```

**WKWebView 里 `outerWidth/outerHeight` 是 0、`screenX` 是 0。**
于是排除矩形 = `[0, 1080, 0, 1080]` —— 空的一条线,
**一次点击都没排除过**。这就是「点软件内部也算一次点击」的直接原因。

### 2.3 就算前端报得准,那张快照也会过期

第二个问题跟窗口几何无关:

- Tauri 的窗口是**贴合内容**的(见 `src/tauri-bridge.js` 的 `fitWindow`);
- macOS 的 `setContentSize` 固定的是**左下角** → 窗口**向上长**;
- 录制列表一出现,内容变高 → 窗口顶边往上跑 → **「结束」按钮移出了开始时那张快照**;
- 于是点「结束」本身被记成了一次「外部点击」。

Electron 侧 `window.screenX` 是准的,但同样是**一张快照**:窗口一动就过期。

### 2.4 修法:排除矩形由**原生层**算,并**实时维护**

| | 矩形的来源 | 谁来刷新 |
| --- | --- | --- |
| Tauri | `WebviewWindow::outer_position()` + `outer_size()` | 窗口事件 `Moved` / `Resized` → 重算 |
| Electron | 主进程 `BrowserWindow.getBounds()` | 窗口事件 `move` / `resize` → 重算 |

两条要注意的细节:

1. **物理像素 → 逻辑点**。Tauri 报的是物理像素,CGEvent 报的是逻辑点
   (左上角为原点)。不换算的话,Retina 屏(缩放 2)上矩形会大一倍,
   半个屏幕的点击都会被当成「点在自己身上」。换算在
   `rec::rect_from_physical` 里,有单测。
2. **前端不再传矩形**。前端那份是不可信的快照,原生层自己算得出的东西
   不要让前端再传一遍(ADR-0013 的「界面层照搬」不受影响:
   `cnc.startRecording()` 两边签名一致)。

### 2.5 为什么不用 `CGWindowListCopyWindowInfo`

本来想用「点的时候问系统:这个点在本应用的哪个窗口里」—— 这样连刷新都不用管。
**实测走不通**:macOS 14+ 在没有「录屏」权限时,
`CGWindowListCopyWindowInfo` 返回的字典**内容是空的**:

```
window count = 24
{ } { } { } ...        ← 每个窗口的字典都是空的
```

`kCGWindowOwnerPID` / `kCGWindowBounds` 全都取不到(值是 null)。
让用户去开「录屏」权限换这一点,不值得 —— 自己算窗口位置不需要任何权限。

### 2.6 真机自检(带对照组)

光看代码不算数。加了一个**自检**:往自己窗口里发一个**合成点击**,
看它会不会被记成一次点击。它是**两组对照**,同一个位置、同一个点击,
只换排除矩形:

- ① 把排除矩形**关掉** → 这个点击**应该**被记下来
  (证明事件监听确实收到了合成点击;没收到 = **这次测不了**,不是「通过」);
- ② 把排除矩形设成**当前窗口** → 这个点击**不应该**被记下来。

Tauri 版真机结果(启动参数 `--diag-recording-exclusion`):

```json
{ "conclusive": true, "control": 1, "excluded": 0, "posted": true,
  "point": [704, 171], "rect": [700, 111, 1220, 409] }
```

- `control: 1` → 对照组成立:合成点击确实被监听到了;
- `excluded: 0` → 排除矩形生效:**点自己界面上的按钮不会被记成一次点击**。

> ⚠️ 自检必须用 `open -a` 正常启动(带参数 `--args`)。
> **从终端直接跑二进制会拿不到辅助功能身份** —— 实测那样跑
> `control: 0`(合成点击被系统丢掉),自检会如实报 `conclusive: false`。
> 这不是代码问题,是启动方式的问题。

## 三、录到的点击要能单条删除

### 3.1 改动

- **原生层**新增「删掉第 index 次点击」:
  - Tauri:`remove_recording_click(index)` 命令;
  - Electron:`removeRecordingClick(index)`(N-API 导出)。
- **界面层**:每条点击旁边一个「×」,点它只删这一条。
  「清空」按钮**保留**(它是全清,不是被替代)。
- 两边界面逐字相同(`src/panels/ClickPanel.jsx` 逐字一致,
  `src/App.jsx` 只差既有的 Tauri 专有部分)。

### 3.2 顺带修掉的两个不一致

1. **停止录制时不再清空原生列表**(两边都改)。
   之前 Electron 在 stop 时清空、Tauri 不清 —— 不清就没法在原生那份上做单条删除,
   两边也对不上。现在两边都留着,「删一条」时两边同步删同一条。
2. **Tauri 的 `stop_recording` 原来返回 bool**,而界面按数组用
   (`Array.isArray(clickData)`)→ Tauri 侧「录制已停止(返回 **0** 个点击)」
   **永远显示 0**。现在 Tauri 与 Electron 一样返回点击数组。

### 3.3 回归

新增 `tools/verify/verify-recording-ui.cjs`(两边逐字相同):

- 走一遍真实流程:开始(倒计时 3 秒)→ 录制中 → 停止;
- 停止后每条点击旁边都有「×」,「清空」还在;
- 点第 2 条的「×」→ 原生侧只被调一次 `removeRecordingClick(1)`,
  界面上剩两条,坐标分别是 (100,200) 和 (500,600)
  (删掉的确实是中间那条 (300,400);序号会重新编,所以看坐标不看序号);
- 另外断言 `startRecording` **不带任何参数** —— 前端不再传那张会过期的矩形。

变异自检:把「×」按钮去掉 → 用例转红
(`有一条点击旁边没有删除按钮:「第1次: (100, 200)」`)。

## 五、留给以后的三句话

1. **窗口位置要用原生 API 拿**,别信 WKWebView 的 `window.screenX`
   (实测是 0)。而且要**除以缩放系数**换算成逻辑点。
2. **排除矩形不能是快照**。窗口会动、会变高(而且是往上长)。
3. **滚动条的轴向规则**:`overflow-y: auto` 会把 `overflow-x` 也变成 `auto`。
   横向动画 + 纵向滚动要共存,就得把横向单独写死。
