# 两条发布线:Windows 与 macOS 各干各的

> **本仓库只放 Tauri 版**。同一个产品的另一个正式版本(Electron 版)在独立仓库
> [`Campus-Network-Connector-Electron`](https://github.com/GOJOCLOUD/Campus-Network-Connector-Electron),
> 两者**同等优先**,只是技术栈不同。
>
> 本仓库内部分 `mac` / `win` 两条线:平台范围口径见
> **[ADR-0012](../06-决策/ADR-0012-平台功能范围-macOS全量-Windows精简.md)**。
> 接手之前先读完这一页,免得把两条线又拧到一起。

## 一句话

`mac` 分支是 **macOS 线**,`win` 分支是 **Windows 线**。

**两个平台不共用一个打包入口**:各自分支、各自的打包配置(`tauri.conf.json` /
`tauri.windows.conf.json`)、各自的 GitHub Actions workflow
(`build-tauri-macos.yml` / `build-tauri-windows.yml`)。macOS 的包不含任何 Windows 专属的
东西,Windows 的包也不含 macOS 专属的东西(Safari 复制修复走 Apple Events,只有 macOS 有)。

**两条线不再同步推进,也不再保持一模一样**:各自的功能、界面、实现、打包产物、
发布节奏都会各自演化。一边想用另一边的改动,**必须显式搬过去**,不会自动流过去,
也不需要保持一致。
> **2026-10-24 补充:「行为一致」是要求,「实现一样」不是。**
>
> 上面那句「不再保持一模一样」说的是**实现、打包配置、文档措辞各自演化**;
> 用户现在明确要求的是**同一个功能在两个平台上的行为必须一致** ——
> 快捷键与触发规则、latch 语义、错误处理与提示、界面结构与文案、门禁,都要对齐。
> 两边**确实不一样**的地方,只允许是「平台必需」(如 Windows 没有「辅助功能」权限、
> 没有 Safari)或「已定产品差异」(见 ADR-0012)。**别拿"两条线不一样"当借口不修 bug。**


## 底层环境:两条线已经分好了

| | macOS 线 | Windows 线 |
| --- | --- | --- |
| 分支 | `mac` | `win` |
| 原生实现 | Rust + CoreGraphics(**无 `.node`**) | Rust + Win32(SendInput / Unicode 键入) |
| 原生代码位置 | `tauri-app/src-tauri/src/commands/native/macos.rs` | `.../native/windows.rs` |
| 录制 | `.../native/recording.rs`(CGEventTap,ListenOnly 监听) | `.../native/recording_stub.rs`(占位,不做) |
| 打包命令 | `npm run tauri:build:mac` → `.app` → zip | `npm run tauri:build:win` → NSIS exe |
| 打包配置 | `tauri-app/src-tauri/tauri.conf.json` | 同左(`tauri.windows.conf.json` 存在,但**当前没有任何构建命令用上它** —— npm 脚本与 CI 都没带 `--config`) |
| CI workflow | `build-tauri-macos.yml` | `build-tauri-windows.yml` |
| CI runner | `macos-latest`,Node 22 | `windows-2022`,Node 22 |
| 界面自检 | `tools/verify/verify-ui-platforms.cjs`(两个平台一起跑) | 同左 |
| 原生自检 | `cargo test --test feature_test` | 同左(非 macOS 分支用 stub) |
| 本机开发 | `npm run tauri:dev` | 同左 |
| Node 版本 | `.nvmrc` → 22 | `.nvmrc` → 22 |
| 功能范围 | 全量(激活 / 文件 / 点击 / 键入 / 输入源 / 录制 / 回放 / keepalive / 拼音 / 剪贴板 / Safari 修复) | **拼音自动键入** —— 见 ADR-0012(2026-10-24 修订:「默认执行(回放)」那一屏已撤掉) |

**本机不打包 Windows**:Windows 打包需要 `llvm-rc`(资源编译器)与 Windows SDK,本机不装,
Windows 产物一律走云端 CI。本机只保留 `x86_64-pc-windows-msvc` 这个 Rust 目标做代码
类型检查(`./tools/windows-check.sh` 一条命令;里面用的 `tools/windows-check-rc-stub.sh`
是替身脚本,不是真工具)。

**与 Electron 版共用的只有三样**,别的一概别指望:

1. `src/` 里的界面骨架(Stepper + panels 的结构)——两个仓库各有一份拷贝,不是同一份;
2. 激活授权那套逻辑(纯 JS + tweetnacl,没有平台依赖);
3. `tools/verify/verify-ui-platforms.cjs` 这条自检(它同时断言两个平台各自的界面)。

其余的——运行时、原生实现、打包配置、CI、依赖、文档措辞——**各自分开**。

## 两条线的关系

- 两个分支**不再同步推进**,也不再保持一模一样。各自的功能、界面、实现、打包产物、
  发布节奏都会各自演化。
- 一边想用另一边的改动,**必须显式搬过去**,不会自动流过去。
- **同一个文件在两条分支上不一样,属于正常状态,不用去对齐。**

## 两个仓库之间的约定

1. **不互相回流**:本仓库的改动不会自动进 Electron 版仓库,反过来也一样。
   要搬就**显式搬**,并在提交说明里写清搬的是什么。
2. **只提交自己动过的文件**:`git add <具体路径>`,不要 `git add -A`。
3. 动共享文件(`src/`、`package.json`、`docs/`)之前先 `git status` 看一眼。
4. **两边同名文件不一样属于正常状态**——那是各自演化的结果,不是待修的不一致。
5. 各自 CI 各自跑:一边绿了不代表另一边绿,别拿一边的结果替另一边背书。
6. 平台专属的功能/界面改动,**只在自己的分支上做**。

## 接下来怎么走

- **功能范围已定稿(2026-10-22)**:macOS 线**全量保留**现有功能;
  Windows 线**只保留拼音自动键入**,
  录制 / 回放 / keepalive / 设为当前输入源在 Windows 侧**不做**
  (2026-10-24 修订:「默认执行(回放)」那一屏从 Windows 界面上撤掉了);
  浏览器字体纠正走 Chrome/Edge 扩展,独立于桌面应用。
  完整清单与口径见 **[ADR-0012](../06-决策/ADR-0012-平台功能范围-macOS全量-Windows精简.md)**。
- **打包一律走 GitHub CI**:推分支即触发,产物作为 release 附件发布;本机只做开发、
  类型检查与测试,不打包 Windows。
- macOS 产物要「辅助功能」权限才能发出模拟点击 / 键入;没权限时应用会**直接报错**,
  不再"显示成功却什么都没发生"。见
  [安装指南(macOS · Tauri)](../05-运维/安装指南-macOS-Tauri.md)。
