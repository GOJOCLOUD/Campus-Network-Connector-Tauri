# 两条发布线:Windows 与 macOS 各干各的

> **这份文档是给并行工作的 Agent 看的。**
> 仓库里同时有两个 Agent 在推进(一个做 macOS/Tauri,一个做 Windows),
> 接手之前先读完这一页,免得把两条线又拧到一起。

## 一句话

`main` 是 **macOS 线**,`windows` 是 **Windows 线**。

**从 2026-10-21 起,两条线不再同步推进,也不再保持一模一样。**
各自的功能、界面、实现、打包产物、发布节奏都会各自演化。
一边想用另一边的改动,**必须显式搬过去**,不会自动流过去,也不需要保持一致。

## 底层环境:两条线已经分好了

| | macOS 线 | Windows 线 |
| --- | --- | --- |
| 分支 | `mac` | `win` |
| 原生模块 | `mac-coregraphics`(CoreGraphics / Carbon) | `win-input`(Win32: SendInput / 低级鼠标钩子) |
| 原生模块构建 | `npm run build:native`(clang++ 直接编 .mm) | `npm run build:win-native`(node-gyp 编 .cc) |
| 打包命令 | `npm run dist:mac:arm64` → `.app` → zip | `npm run dist:win` → NSIS exe |
| 打包配置 | `package.json` 的 `build.mac` | `package.json` 的 `build.win` |
| 原生模块解包 | `asarUnpack: mac-coregraphics/**` | `asarUnpack: win-input/**` |
| CI workflow | `build-desktop.yml` | `build-windows.yml` |
| CI runner | `macos-latest`,Node 22 | `windows-2022`,Node 22 |
| 产物自检(硬门禁) | `tools/verify/verify-package.cjs` | `tools/verify/verify-package-win.cjs` |
| 界面自检 | `tools/verify/verify-ui-platforms.cjs`(两个平台一起跑) | 同左 |
| 本机开发 | `npm run electron` / `npm run electron:build` | 同左(脚本已用 cross-env,cmd 下能跑) |
| Node 版本 | `.nvmrc` → 22 | `.nvmrc` → 22 |
| 特有能力 | Safari 复制修复(Apple Events)、录制、回放、keepalive、快捷输入 —— **全量保留** | **只保留拼音输入 + 浏览器字体纠正(走 Chrome/Edge 扩展)** —— 见 ADR-0012 |

**只有三样东西还是共用的**,别的一概别指望:

1. `src/` 里的界面骨架(Stepper + panels 的结构)目前还是同一份;
2. 激活授权那套逻辑(纯 JS + tweetnacl,没有平台依赖);
3. `tools/verify/verify-ui-platforms.cjs` 这条自检(它同时断言两个平台各自的界面)。

其余的——原生模块、打包配置、CI、依赖、文档措辞——**各自分开**。

## 共同起点

两条线最后一次"同步"是从 `d421777`(Tauri shell 那次提交)分出去的,
之后各自往前走,**不再回流**。所以:

- `windows` 分支上现在有、但 `main` 上没有的东西,通常就是 Windows 线自己的选择(比如 `win-input`、NSIS 配置);
- 反过来也一样(`main` 上的 Tauri 工程、mac 的 ad-hoc 签名、参考库重建等)。
- **同一个文件在两条分支上不一样,属于正常状态,不用去对齐。**

## 并行 Agent 的协作约定

1. **只提交自己动过的文件**:`git add <具体路径>`,不要 `git add -A`。
   否则会把别人在途的改动一起卷进自己的提交 —— 这个坑已经踩过两次
   (别人的 Tauri 提交里混进了 Windows 侧的改动,标题也对不上)。
2. 动共享文件(`src/`、`package.json`、`docs/`)之前先 `git status` 看一眼:
   有别人的在途改动,就换个文件、或者先说一声,别覆盖。
3. 提交前 `git log -3` 看看有没有别人的新提交刚进来。
4. **两条线之间的冲突不用解**。同一个文件在两条分支上本来就可能不一样,
   那正是"不同步"的正常表现。
5. 各自 CI 各自跑:一边绿了不代表另一边绿,别拿一边的结果替另一边背书。
6. 平台专属的功能/界面改动,**只在自己的分支上做**,不要想着"两边一起改"。

## 接下来怎么走

- **功能范围已定稿(2026-10-22)**:macOS 线**全量保留**现有功能;
  Windows 线**只保留拼音输入 + 浏览器字体纠正**,
  录制/回放/keepalive/设为当前输入源在 Windows 侧**不做**。
  完整清单与口径见 **[ADR-0012](06-决策/ADR-0012-平台功能范围-macOS全量-Windows精简.md)**。
- **macOS 正在换技术架构**(Tauri 版)→ 按 ADR-0012 的全量清单逐项补齐,
  补完才算迁移完成。
- 工作只在本地进行,不再往 GitHub 推;目录最终由人拷到 U 盘带走。
  需要出包时,在各自线上本地构建(Windows 线需要 Windows 机器或临时开一次 CI)。
