# 工具与文件的分工（定稿）

> 这份文档是**判据**：任何时候不清楚"这个东西该放哪、该不该删"，看这一页。
> 与 [ADR-0012](../06-决策/ADR-0012-平台功能范围-macOS全量-Windows精简.md)（功能范围）配套。

## 一句话

**文件放仓库，工具装系统。** 两者不能互相代替，也不能互相顶替。

## 文件：仓库里的东西

| 项 | 说明 |
| --- | --- |
| 是什么 | 源代码、配置、CI workflow、文档、脚本 |
| 在哪 | 仓库里，跟着分支走，git 管 |
| 特性 | 提交上去就有，谁 clone 谁都有；**删文件等于删代码** |
| 规矩 | **只增不删**。每个分支放本平台的代码 + 本平台的打包文件 |

### 分支里放什么

| 仓库 | macOS | Windows |
| --- | --- | --- |
| 旧仓库 `Campus-Network-Connector` | `main` | `windows` |
| `Campus-Network-Connector-Electron` | `mac` | `win` |
| `Campus-Network-Connector-Tauri` | `mac` | `win` |

- **分支是代码的存放处，必须存在**。删分支 = 那一半代码没了。
- 两条线**不自动回流**：一边要用另一边的改动，必须**显式搬过去**。
  同一个文件在两条分支上不一样属于正常状态，不用去对齐。
- `mac` 分支同时保留 Windows 的打包文件（`build-tauri-windows.yml`、`tauri.windows.conf.json`）——
  这样在 Actions 页面上还能**手动触发**一次 Windows 构建（ref 选 `win`）。

## 工具：系统里装的东西

| 项 | 说明 |
| --- | --- |
| 是什么 | 编译器与构建器本身：rustc、cargo、node、npm、tauri CLI，以及 Rust 的交叉目标 |
| 在哪 | 本机系统里，**不进 git**，占本机磁盘 |
| 特性 | 装了就一直在；跟分支无关，任何分支都能调；**不装就没有** |
| 规矩 | **绝不往仓库里塞工具**。分支里只会有文件 |

### 本机装什么、不装什么

| 工具 | 本机 | 为什么 |
| --- | --- | --- |
| node / npm / cargo / rustc / tauri CLI | **留着** | macOS 线的开发与构建要用 |
| `x86_64-pc-windows-msvc` 交叉目标 | **留着** | 让本机能做 **Windows 代码体检**（`cargo check --target`），提前发现"显眼错误"，不必等 CI 回传 |
| `llvm-tools` / `llvm-rc` 等资源编译器 | **不装** | 只有 Windows **打包**才需要；打包在云端做 |
| 任何 Windows 打包链的东西 | **不装** | 同上 |

### Windows 代码体检怎么跑

```bash
./tools/windows-check.sh
```

一条命令就够（RC 替身的绝对路径它自己算好了）。

底层是 `cargo check --target x86_64-pc-windows-msvc`：只做类型检查，不打包、不链接。

`tools/windows-check-rc-stub.sh` 是**文件**（脚本），不是安装的工具。
它只替代 tauri-build 那一步"编译 Windows 资源(.rc)"——那步要真的资源编译器，
是打包用的。`cargo check` 只做类型检查、不链接，资源那步的结果毫无意义，
所以给它一个替身即可：**只影响检查，不影响任何打包产物**（云端 CI 有真的资源编译器）。

> RC 的路径**必须给绝对路径**：编译 .rc 那步跑在 cargo 依赖的构建脚本里，
> 工作目录在 `~/.cargo/registry` 下，相对路径会解析到那里去，
> 结果是 `Couldn't execute ../../tools/... No such file or directory`。
> `tools/windows-check.sh` 已经把这件事封掉了，不用自己拼路径。

> 这个替身已经抓出过一次真错误：`pub use recording_stub as rec` 重导出私有模块
> （E0365），Windows 上编译不过 —— 当时只有 CI 报错，本机体检是 0 成本提前发现。

## 打包：在云端，不在本机

- **所有打包一律走 GitHub Actions**（免费仓库、构建次数不限；出问题日志和产物直接回传）。
- 本机**不打包 Windows**。
- 本机只做：开发、类型检查（含 Windows 目标）、单元测试、界面自检、装包后跑起来看运行自检。

## 权限分层（macOS，容易踩坑）

| 能力 | 需要什么授权 | 没有会怎样 |
| --- | --- | --- |
| 录制（监听左键点击） | **不需要**（listen-only 的会话级事件监听） | — |
| 模拟点击 / 回放 / 拼音自动键入 | 「辅助功能」 | 事件被系统**静默丢弃** → 现在会**直接报错**并在界面给授权指引 |
| Safari 复制修复 | 「自动化」 | 界面**会**显示失败原因和授权指引 |

详见 [安装指南-macOS-Tauri](../05-运维/安装指南-macOS-Tauri.md)。

## 平台功能范围（摘要）

- **macOS 线：全量保留**（Electron 版现有功能一个不少）。
- **Windows 线：只保留** ① 拼音自动键入 ② 浏览器混淆字体纠正（走 Chrome/Edge 扩展，
  独立于桌面应用）；**不新增** 录制 / keepalive / 设为当前输入源；
  **「默认执行（回放）」这一屏也不保留**（2026-10-24 修订：Windows 不做录制 ⇒
  没有可回放的源 ⇒ 那一屏是「点了没反应」的死界面，见 ADR-0026）。

完整口径见 [ADR-0012](../06-决策/ADR-0012-平台功能范围-macOS全量-Windows精简.md)。
