# 已知限制与失败场景

按"会怎么处理"来组织。原则：**宁可什么都不改，也不输出猜测出来的文字**。

---

## 1. 明确的能力边界

| 限制 | 影响 | 当前行为 |
| --- | --- | --- |
| 参考库只含 GB2312 字符集（6763 汉字）+ 常用符号 | 生僻字、少数民族文字、emoji 不在库内 | 该字符判为"无参考字形"，不参与映射；若同作用域其它字符可还原，则该字符保持原样并计入未还原数 |
| 单字符渲染比对 | 依赖上下文改变字形的排版（连字、上下文替换 GSUB）无法识别 | 逐字符渲染 → 这种字形不会被认出 → 不还原（安全降级） |
| 跨风格（衬线 vs 无衬线）准确率约 90% | 约一成字符无法还原 | 置信度门限内精确率 100%；门限外的字符保持原字符，**不猜** |
| 作用域投票需要样本 | 只选中 1~2 个字符时判定依据较弱 | 单字符时仍要求 `margin≥0.01 / score≥0.8 / selfDistance≥0.15` 四条全中 |
| 只在文本节点上取样式 | `text-transform`、图片文字、canvas 里的文字无法还原 | 不处理 |
| 密码框 / 输入框 | — | 选区在 `input`/`textarea` 内时不做任何改写，保持原生行为 |

---

## 2. 会保留原始复制结果的场景（不伪造）

1. **参考库里没有该字符** → 该字符不替换。
2. **最近邻置信度不足**（margin < 0.01 或 score < 0.8）→ 不替换。
3. **字形与自身参考字形太接近**（selfDistance < 0.15，说明字体画的就是它自己）→ 不替换。
4. **DOM 分段与原生选区文本对齐失败** → 整段跳过（宁可漏改也不错位）。
5. **作用域投票未达 60%** → 认为不是混淆字体，一个字都不动。
6. **浏览器没有提交事件里的 clipboardData** → 退化到浏览器的原生复制结果。

---

## 3. 已知的副作用

1. **"复制为 Markdown"类网站会被还原成可见文本**。
   我们的 `observe` 模式把"页面改写了 text/plain **且** 调用了 preventDefault"
   判定为篡改并拦下其 preventDefault，于是浏览器提交原始选区。
   这正是任务书第二级要求的直接后果；若这类站点影响较大，
   第二阶段应加"按站点豁免"开关。

2. **页面在 `mousedown` 里用 `navigator.clipboard.writeText()` 抢先写入**：
   浏览器随后执行原生复制会覆盖它；若页面同时 preventDefault 且被我们拦下，
   我们提交的是原始选区（而不是它写的内容）→ 用户拿到的是可见文本，符合预期。

3. **页面在 copy 前清空选区**（`selectstart` 里 `getSelection().removeAllRanges()`）：
   复制时选区已空，我们无从还原 → 复制结果为空/异常。
   这是目前未覆盖的场景，第二阶段可考虑在 `selectstart` 阶段记录选区快照。

4. **扩展会在页面根节点上写一个 `data-copy-repair` 属性**（只含计数，不含用户文本），
   用于 e2e 与排障观察扩展状态。正式发布前可以移除。

## 4. 平台差异

### Windows 11
- 未在本机验证（本仓库的验证环境是 macOS）。Chromium 内核行为一致，
  但**快捷键、剪贴板提交、系统区域设置**都未实测。

### macOS Safari
- **扩展打包被签名资格卡住**：free 个人团队签不出 Safari Web Extension 扩展点的描述文件，
  产物虽然编译/签名成功，但 Safari 不加载（设置里扩展列表为空）。需付费开发者团队。
  → 已提供**热键工具**替代路径：不依赖扩展、不依赖签名，实测 3/3 通过。
- **页面内守卫的副作用**：接管复制时会调用 `stopPropagation()`，网页因此**收不到 copy 事件**
  （依赖 copy 事件的网页增强功能在"我们修复时"会失效）。
  仅在**存在可信字体映射**时才接管，普通网页不受影响。
- 热键工具是**复制后修正**（拿不到 copy 事件），因此：
  - 复制富文本时只能修 text/plain 那一路；
  - 篡改恢复默认关闭（需 `--restore`），且只在剪贴板与可见文字**毫无共同字符**时才动手，
    避免误伤「用户复制的是 URL/代码」这类场景。
- `world: "MAIN"` 不被 Safari 的 manifest 转换器支持 →
  **第二级（copy 事件篡改）修复在 Safari 上会降级**，字体混淆修复不受影响。
- Safari 扩展必须由用户手动启用一次（见安装指南）。

### Safari 原生 App 路线（Apple Events 注入，实测可用）

不依赖扩展与签名，由原生 App 通过 Apple Events 把守卫注入当前标签页。已实测通过，
但有明确边界：

| 限制 | 实测结论 |
| --- | --- |
| **跨源 iframe 完全无解** | 注入跨源 iframe 抛 `SecurityError`；copy 事件也不跨 frame 冒泡。只能覆盖同源 frame（真实目标页的题目在第 4 层同源 frame 内，覆盖成功）。 |
| **@font-face 在跨源样式表里读不到** | 页面拿不到字体文件 → 该作用域不做替换（安全降级，保留原始复制）。可用 Resource Timing 里的 URL 由主进程兜底下载，本版未做。 |
| **需要用户手动开一次系统授权** | Safari → 设置 → 高级 → 勾选「显示网页开发者功能」→ 开发 → 允许来自 Apple Events 的 JavaScript。未授权时状态里 `lastError` 会记录原因。 |
| **明文生僻字匹配不到就不还原** | 参考库覆盖 GB2312(7949 字)；匹配不到的字保持密文原样，其余照常还原。 |
| **不是所有混淆字体都能解** | 若字体把明文字形**大幅重绘**（本例实测重绘，相似度 0.87~0.97），最近邻可能分不清 → 置信度闸门会拒绝替换，宁可留错字也不写错字。 |
| **「前台标签每轮都处理」这条通路实测不生效** | AppleScript 的 `index of front tab of front window` 实测**恒等于 1**（不是真正的当前标签）→ 非目标站点的页面实际上没被接管。**目标站点不受影响**（走站点过滤，实测 i.chaoxing.com 正常接管）。Electron 版同一写法，两版本同口径。 |
| **Safari 里大部分标签的脚本上下文是 `about:blank`** | 标签地址还在，但文档上下文是空的 → `do JavaScript` 在这些标签上等于白跑。真实目标标签实测正常。→ **验证时必须按 URL 精确定位标签**，不能用 `front tab`。 |
| **诊断文件是前端的定时快照** | `diag.json` 由前端每 3 秒写一次；App 窗口不可见时 WebView 定时器被系统节流 → 文件会停在旧值，看着像「后台线程死了」其实它好好地在跑。排查时先把窗口亮着再看。 |
| **换题后有约 0.1~0.7 秒的等待** | 映射**下发**到页面要几百毫秒:一次 Apple Event 往返 ≈110ms(每次新起一个 osascript 进程),快通道**名义**间隔 200ms(真实周期 = 工作 + sleep,实测 205ms/工作 110ms)。实测 116~705ms 出明文。**这不是分析慢** —— release 下分析一份真机字体只要 13ms(ADR-0016)。已缓存的字体不用重新分析,但**下发那一步省不掉**。若超过 1 秒还不行,查 `safariRepair.fastPoll`。 |
| **Electron 侧的 `ticksSinceInject` 计数从来没生效**（**已修**,ADR-0018） | 它的键是**字符串**,取的时候用的是**数字**键 → 永远取不到 → 强制重注入从不发生(靠"守卫不在才注入"兜底)。现在两张表统一用 `tabKey()`,并且加了**版本比对**:页面里的守卫旧了就立刻重新注入。 |
| **判活查询与 Electron 版口径不同** | Tauri 线用 `application "Safari" is running`（不需任何额外授权、也不把 Safari 拉起来）；Electron 线仍问 `System Events`（那条路要一份用户从没被授予过的授权 → 静默停掉）。差异原因写进 ADR-0015。 |
| **iframe 桥的 frame 名单靠轮询刷新** | 站点在**嵌套 frame 内部**换 iframe 时，顶层 MutationObserver 看不见 → 现在靠 `take()`/`setMapping()` 前先 `scan()` 兜住。代价是每次收集/分发都走一遍 frame 树（实测 23ms）。 |
| **页面里的旧版守卫要等 App 重新注入才换** | 守卫能按版本号**就地升级**，但前提是有人重新注入它。Tauri 线每 5 轮强制重注入一次（≈1 秒）；Electron 线现在直接比对版本、对不上就立刻重注入。**换 App 版本后，已打开的标签页最长约 1 秒自动换上新版**（或直接刷新那个标签页）。 |

### 两者共通
- headless 模式不提交 copy 事件的 clipboardData 改写 →
  自动化验证必须用有头模式并核对系统剪贴板。

## 5. 性能相关

- 选区分析在**选中时**（防抖 120ms）异步完成，复制事件本身只做查表与拼接。
- 每个不同字符只做一次 canvas 渲染 + 一次参考库检索（两段式：8×8 粗筛 → 32×32 精筛）。
- 后台 service worker 首次使用时加载 1.99MB（gzip）参考库并一次性反序列化，之后常驻。
- 每次选区分析前会作废渲染缓存并重新渲染当前选区的字符 —— 这是字体变更检测的前提，
  代价是每次选择变化会有少量 canvas 渲染（实测毫秒级）。
- 缓存命中时复制路径不触发任何字体解析。

### 窗口贴合内容:macOS 线还留着同一个圈(Windows 已修)

Tauri 版有个 Electron 版没有的机制:**窗口贴合内容** —— 把透明窗口收到只剩
白色卡片那么高(否则窗口周围那圈透明区域**照样吃鼠标事件**,底下的 App 点不动)。

内容区(Stepper 里那个 `overflow-y:auto` 的容器)的 `max-height` 是 **`65vh`**,
也就是**跟着窗口高度走**。于是「量窗口该多高」成了一个圈:

```
窗口高度 → 65vh → 内容区高度 → 卡片高度 → 想要的窗口高度 → 窗口高度
```

每绕一圈就是一次**原生窗口尺寸变化**(WebView 整页重排)。

- **Windows 线已修**(2026-10-24,见 ADR-0026):改成按**内容的自然高度**算,
  目标高度与当前窗口高度无关 ⇒ 一次算准,切页动画期间也不再触发 resize;
  窗口起始高度也改成 640(与 macOS / Electron 对齐)。
- **macOS 线还留着这个圈**:它的窗口起始高度是 640,内容区一次就装得下 ⇒
  实测只绕一圈(640 → 532),看不出来。本轮**没改**(改了会让已交付的 mac 包变旧)。
  真要改就是 `src/tauri-bridge.js` 里那个 `naturalCardHeight` —— 但那条文件
  两分支已经分叉了(Windows 分支那份才有这个函数),改之前要想清楚要不要把两边合回去。

**怎么量**:原生侧记了 `FIT_RESIZE_COUNT`(**实际**改过几次窗口尺寸),
出现在 `get_native_status` 的 `fitResizes` 字段 ⇒ 前端每 3 秒写的 `diag.json`
会带着它。切一步应该只 +1;还是一串数字 ⇒ 贴合内容那条链还在绕圈。

## 6. 隐私边界（代码层面保证）

- 扩展**不申请主机权限**，不发起任何网络请求（参考字形库随包分发）。
- 不读取系统剪贴板历史，不监听剪贴板变化。
- 诊断日志只记录计数、作用域、匹配分数，**不记录复制内容与选区文本**。
- 不在后台持续记录用户行为；`storage` 只用于保存映射缓存。

## 7. 录制与自检（2026-10-23 末之后新增）

- **WKWebView 的 `window.screenX / outerWidth / outerHeight` 不可信**（实测 `0/0/0`）。
  任何"拿窗口在屏幕上的位置"的需求都必须走**原生 API**
  （Tauri 的 `outer_position()` / `outer_size()`，且要**除以缩放系数**换算成逻辑点）。
- **排除矩形不能是快照**：Tauri 的窗口贴合内容，内容变高时窗口**向上长**
  （Cocoa 的 `setContentSize` 固定左下角），所以「开始录制时算一次」必然过期。
  现在由原生层在窗口每次 `Moved`/`Resized` 时刷新。
- **自检需要辅助功能身份**：`--diag-recording-exclusion` 发的合成点击会被系统丢弃，
  除非进程有辅助功能权限。所以：
  - 必须用 `open -a <app> --args --diag-recording-exclusion` 启动（从终端直接跑二进制拿不到身份）；
  - `conclusive: false` 表示**这次没测成**，不是"通过"。
- **Electron 侧在本机无法端到端自检**：合成点击要「辅助功能」权限，
  没授权 → 合成点击被系统丢弃 → 自检报 `conclusive: false`。
  排除逻辑与 Tauri 侧是同一份代码，矩形取自 Electron 自己的 `getBounds()`。
