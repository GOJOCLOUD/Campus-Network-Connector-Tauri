# 故障排查

## 「模拟输入/输入源/录制」按钮点了没反应

1. 看界面顶部有没有红色告警条(原生模块加载失败)
2. 命令行看日志:
   ```bash
   grep "\[native\]" /tmp/app.log     # 或从终端启动 App 直接看输出
   ```
3. 检查安装包:
   ```bash
   node tools/verify/verify-package.cjs "/Applications/模拟输入.app"
   ```
   看「原生模块已解包到 app.asar.unpacked」是否 ✅
4. 常见原因:**只换了 app.asar 没换 app.asar.unpacked**(见 ADR-0003)

## Safari 复制修复不生效

> 下面这套步骤是 **Tauri 版**的。Electron 版的数据目录、诊断文件、脚本都不一样,
> 别把两边的命令混着用(2026-10-22 这次排查就被 Electron 的路径带偏过)。

按顺序排查:

1. **功能开关是否开着**:界面「Safari 复制修复」= 开启
2. **App 是不是退出了**:关窗口不该退出(macOS 惯例)。看进程:
   ```bash
   pgrep -fl simuinput-tauri
   ```
3. **目标页有没有被接管**:页面上应有 `window.__copyRepairGuard`。查:
   ```bash
   osascript -e 'tell application "Safari" to do JavaScript "String(!!window.__copyRepairGuard)" in tab 1 of window 1'
   ```
   - `false` → **守卫根本没装上**(注入失败),看第 5 步的 `lastError`
   - `true` → 守卫在,继续看第 4 步
4. **映射有没有送到页面**:守卫里 `window.__copyRepairGuard.mappings` 应有内容;
   复制时若打出 `copy-no-mapping`,就是映射没到(看第 5 步的 `mapping` 字段)
5. **看诊断文件**(字段含义见下):
   ```bash
   cat "$HOME/Library/Application Support/com.gojocloud.campus-network-connector.tauri/diag.json" | python3 -m json.tool
   ```
   - `safariRepair.enabled` — 开关状态
   - `safariRepair.injected` — 这一轮有没有处理到标签
   - `safariRepair.lastError` — 致命错误(权限/注入失败/参考库缺失)
   - `safariRepair.mapping` — **映射没建起来的原因**(取字体失败/分析失败/映射为空);
     这三种以前全是静默跳过,只看 `enabled` 会以为一切正常
   - `safariRepair.mappingScopes` — **逐个作用域**的映射结果(保留 12 条);
     只留"最后一次"会把真正出问题的那条盖住(页面上常有五六个作用域)
   - `safariRepair.safariRunning` — Safari 在不在跑(`false` = 没开,中性状态不是错误)
   - `safariRepair.runningProbe` — **判活查询的原始结果**;
     看到 `查询失败: …` 就说明判活这一环断了(见下面第 7 步)
   - `safariRepair.poll.lastProbe` / `pollCount` — 轮询看到几个标签、还在不在跑

> ⚠️ **`diag.json` 是前端每 3 秒写一次的快照。**
> App 窗口不可见时,WebView 的定时器会被系统节流 → **文件停在旧值**,
> 看着像「功能死了」其实是「界面没在刷新」。
> 排查时先把 App 窗口亮着再看这个文件(2026-10-22 就被这个坑过一次:
> 误以为后台轮询线程死了,其实它好好地在跑)。

6. **是不是没等到映射**:刚打开页面 1 秒内复制可能还没建好映射 → 等 2 秒再试
7. **判活查询是不是断了**(2026-10-23 真实故障,ADR-0015):
   老口径问的是 `System Events`,那要**另一份**自动化授权,
   用户从来没被提示过 → 查不到 → 被判成"Safari 未运行" → **整个功能静默停掉**。
   症状是:`lastError` = "Safari 未运行"、`poll.lastProbe` **全空**、
   但 Safari 明明开着很多标签。现在改用 `application "Safari" is running`,
   `runningProbe` 字段会直接显示查询结果;再不行就查
   **系统设置 → 隐私与安全性 → 自动化** 里有没有本 App 对 Safari 的授权。

### 换题后立刻复制,还是密文(等约 0.4 秒就变明文)

**这不是功能坏了,是分析还没完成。**
换到**全新字体**(新的 data URI)时,字体分析要重跑一遍:
原先串行很慢(当时实测 11 秒),并行化之后更快。
⚠️ **那两个数是 debug 构建量的**:release 下同一份真机字体只要 **13ms**(debug 慢 25 倍)。
**所以"等分析"从来不是等 2 秒的原因** —— 真正的原因是**映射下发**要 2 秒(见 ADR-0016)。
这段时间里页面上一份映射都没有 → 复制出来必然是密文。

- 已缓存的字体 → 立即可用
- 全新字体 → 稍等再复制。**现在正常的等待是 0.1~0.5 秒**(实测:87~532ms 就能出明文);
  超过 **1 秒**还不行,查 `safariRepair.fastPoll`(快通道是不是活着、有没有盯住那个标签)
- 换题**不换字体** → 映射直接复用,没有这个窗口

### 守卫装上了,但复制出来还是密文

看 `safariRepair.mapping` 字段:

- `取字体失败(url): …` — 字体下载不到(跨源/需要鉴权/地址变了)
- `分析字体失败: …` — 拿到的不是合法字体文件
- `映射为空(字体 N 个码位,都没认准)` — 字体不是混淆字体,或识别置信度不够
  (置信度不够时**故意不改** → 宁可留怪字,绝不写错字)

## 复制出来的还是怪字,但界面显示正常

说明字体识别失败。查:

- 该作用域的字体是否可读(`@font-face` 在跨源样式表里就读不到 → 不还原)
- 识别置信度不够时会**故意不改** → 宁可留怪字

## 复制只修好一半(前半句明文、后半句密文)

这是 2026-10-21 修掉的真实故障(根因见 ADR-0005):查表要两样东西,
"这个字画成了哪个字"来自主进程的映射表(按字体整份下发,不会过时),
但"这个字属于哪个字体作用域"曾经是**采集缓存**——采集比复制慢一拍,
于是**刚选到、还没采集过的新密文字**查表落空 → 原样进剪贴板。
早先选过的字在缓存里 → 修好了(所以看起来"只修好一半")。

**现在复制时当场按当前选区解析作用域,不再依赖缓存。**
如果又出现同样现象,先确认页面里的守卫版本:

```bash
node tools/lab/diag-frames.cjs chaoxing        # 看每层 frame 的守卫状态与作用域
node tools/lab/diag-apply.cjs <tab> judge      # 逐字复算查表路径,看是谁落空
node tools/lab/verify-fastcopy.cjs --tab <tab> # 清空采集缓存后立刻复制,必须全还原
```

`verify-fastcopy.cjs` 是这个故障的**回归测试**:它清空采集缓存再复制,
旧守卫会红(剪贴板留原样密文),新守卫必须零残留。

## 打包后 App 起不来 / 功能全废

跑 `node tools/verify/verify-package.cjs`,逐项对照。

## 标签页序号对不上

Safari 的标签序号会变(关标签/重排)。**不要用固定序号**,用 URL 定位
(`tools/verify/verify-app-e2e.cjs` 里是按 URL 找的)。

## Windows 上快捷键没反应

> ⚠️ **2026-10-27 起,Windows 线抢 ⌃D(主键)+ ⌃⇧D(容错别名),不抢 ⌃S**(ADR-0031)。
>
> - **⌃D(读剪贴板并键入)**:我们**要抢**它 —— 抢到手,别的软件就**收不到** Ctrl+D,
>   那个软件也就不会被自己的「收藏夹 / 退出」之类动作干掉
>   (用户口径:「干脆直接把系统的抢了,我的软件优先级最高」)。
>   ⚠️ **代价要知道**:⌃D 在 Edge/Chrome 是收藏夹、VS Code 是选中下一处、Excel 是向下填充
>   ⇒ **本软件开着的时候,别的软件里按 Ctrl+D 它们收不到**。这是抢全局键的固有代价。
>   ⚠️ 但注册是**系统级独占**的:别的软件先注册了同一个组合键 ⇒ 我们**抢不到**
>   ⇒ 按 ⌃D **不会触发我们**,而目标软件自己的 Ctrl+D **照常生效**
>   ⇒ **抢没抢到,界面上直接写着**：「键盘输入」页有一条**琥珀色提示**
>   「Ctrl+D 没抢到(这个组合键被别的软件先注册了):按它不会触发我们,
>   目标软件自己的 Ctrl+D 也会照常生效。」
>   —— **看到那条提示 = 没抢到**(不是软件坏了)。
> - **⌃⇧D 是容错别名**(同一个动作):系统的全局热键是**精确匹配**,
>   手上多带一个 Shift 时 ⌃D 不会触发 ⇒ 别名把那条路兜住。
> - **⌃S**:**仍然不抢**(Windows 上「默认执行」那一屏已经撤了,ADR-0026;
>   而且 Ctrl+S 在别的软件里是「保存」,抢过来会把人家的保存弄坏)。
>   ⇒ 「按 ⌃S 没反应」在 Windows 上是**预期行为**。
>
> 诊断里能一眼确认:
>
> ```jsonc
> // diag.json 的 shortcuts 段
> "shortcuts": {
>   "registered": ["Control+D", "Control+Shift+D"], // ← 里面有 Control+D = 主键抢到了
>   "globalShortcutsEnabled": true,           // ← 全局键这条路是**开**着的
>   "pasteRegistered": true,                  // ← ⌃D **抢到了没有**(false = 没抢到)
>   ...
> }
>
> // 原生状态(get_native_status)里另有一栏:
> "shortcutPasteRegistered": true             // ← false = **没抢到**
> ```
>
> 下面这几步是排查步骤 —— 2026-10-24 之前全局键是**关**的,现在**开**了,正好用得上。
>
> ⚠️ 2026-10-25 修过一处:`globalShortcutsEnabled` 在 Windows 上原来还写着 `false`
> (那是「一个全局键都不占」那版留下的)⇒ 会让人以为「按政策不注册」。
> 现在它恒为 `true`;**分清「抢到了/没抢到」看 `registered` 和 `pasteRegistered`**。

按**三步**查,顺序不要乱 —— 一步比一步窄:

### ① 先查热键**注册**成功没有

全局快捷键在 `diag.json` 的 `shortcuts` 段:

```jsonc
"shortcuts": {
  "registered": ["Control+Shift+D"],          // ← 这里少了 Control+Shift+D = 注册失败
  "defaultExecute": "Control+S",             // ← 记着,但 Windows 线**不注册**它
  "paste": "Control+Shift+D",
  "tap": { "alive": true, "error": "", "latchArmed": true, "...": "..." },
  "hits": [ ... ]                             // ← 有没有命中记录
}
```

- `registered` **少了 `Control+D`**(或整段空)⇒ **系统没注册成功**。
  Windows 的全局热键是**独占**的:别的软件已经占了 `Ctrl+D`
  ⇒ 注册失败(`registered` 里就没有它)。
  ⇒ 界面上的「没抢到」提示说的就是这件事(见上面)。
  临时验证办法:先用别的软件把这个键放掉,或换个别的键试。
- `registered` 有 `Control+D`,但 `hits` **一直是空** ⇒ 系统把组合键送来了、但**没进到我们的动作**,
  往 ② 看。

### ② 再查 Control 的**边沿观察**能不能用

`tap` 段里:

- `latchAvailable: false` ⇒ **拿不到 Control 的按下/松开**(观察线程没起来)
  ⇒ latch **降级为不生效**(快捷键一律放行)。这时快捷键应该**能用**;
  如果这时也不能用,问题不在 latch,在 ①。
- `latchArmed: false` ⇒ latch **锁着**(上一次触发之后 Control 一直没松开)
  ⇒ **这是设计如此**:必须**松开 Control 再重新按住**才恢复。
  用户按住 Ctrl 连按 S 只会触发一次 —— 那是 latch 的本意(「默认执行」是回放,
  触发多次就是往屏幕上乱点)。
- `ctrlObserver` 那一栏恒为 `"GetAsyncKeyState(VK_CONTROL)"` ⇒ 观察源是哪个,
  换实现时记得同步改这里。

### ③ 最后查**动作**有没有执行

`hits` 段里每次命中都记一笔:

```jsonc
{ "key": "⌃D", "outcome": "已键入 12 个字符", "inputSource": "无(该平台没有输入源概念)" }
```

- `outcome` 是「剪贴板是空的」⇒ 剪贴板里没文本(或者剪贴板读不到)。
  Windows 上剪贴板是**全局资源**,别的程序正开着它就会读不到
  (自检里会重试 5 次;仍然失败就是真被别人占着)。
- `outcome` 是「键入失败:…」⇒ `SendInput` 被拦下了
  (权限/安全软件/UIPI)—— 看提示原文。
- `hits` 里**有**这条、但屏幕上没反应 ⇒ 文本敲到别的窗口去了:
  确认焦点在哪个应用。

### ⌃D 在**某个软件**里不管用,但别的软件里正常

**现象**(2026-10-27 真人反馈):**在微信里**按 ⌃D 是微信自己的动作,
我们的「读剪贴板并键入」不触发;在别的软件里按 ⌃D 一切正常。

**这和「没抢到」是两回事** —— 注册**是好的**,界面上也**没有**琥珀色提示。
根因:**两种「抢」不在同一层**。

| | 机制 | 优先级规则 | 能不能被绕过 |
| --- | --- | --- | --- |
| 我们的实现 | `RegisterHotKey`(系统全局热键) | **先注册先得** | 不能 |
| 微信这类软件 | **低级键盘钩子**(`WH_KEYBOARD_LL`) | **后装的钩子先被调用** | 能(钩子返回非 0 就把键吞掉) |

Windows 的输入顺序是:**低级钩子 → 系统热键 → 目标窗口**。
微信的钩子在**系统热键之前**就把 Ctrl+D 处理掉了(多半还吞掉)
⇒ 我们**根本收不到 `WM_HOTKEY`** ⇒ 日志里也不会出现「⌃D 直输」那一行。

**当场确认是不是这种情况**(2026-10-27 在真机上做过):

1. 启动日志里 `[shortcut] Ctrl+D=true` ⇒ **系统热键注册是好的**,不是被抢占;
2. 用一个自己的进程调 `RegisterHotKey(Ctrl+D)`:
   - 失败(错误码 **1409** `ERROR_HOTKEY_ALREADY_REGISTERED`)⇒ 这个组合键
     **系统里有人占着**(实测:把我们自己退出后再调就拿到了 ⇒ 占用者是我们自己);
   - ⇒ 微信**没有**用系统热键占这个键 ⇒ 它走的是**钩子**那条路。

**已经改好了(2026-10-27)**:我们自己也装了一个**低级键盘钩子**
(`WH_KEYBOARD_LL`),看到 ⌃D 就**吞掉它** ⇒ 微信收不到、系统热键也收不到
⇒ 只有我们响应(详见 ADR-0033)。

⚠️ 但**不是绝对保证**:Windows 的规则是**后安装的钩子先被调用**
⇒ 本软件**后启动**就赢;对方后启动就对方赢。

**怎么看钩子装上了没有**:`diag.json` 的 `shortcuts.hookCtrlD` = true 就是装上了。

没装上时**如实降级**:还有系统热键那一路能用,只是压不过用钩子的软件。

### 一句话流程

**注册成功吗 → Control 观察能用吗 → 动作执行了吗**,
三步分别对应 `registered` / `latchAvailable`+`latchArmed` / `hits.outcome`。

## 点叉之后窗口找不到了 / 想退出却退不掉(2026-10-24 新增;2026-10-25 两次改口径)

Windows 线上右上角现在**只有两个**按钮:

| 按钮 | 图标 | 干什么 |
| --- | --- | --- |
| 最小化 | — | 窗口缩到任务栏 |
| **叉叉**(=「终止」) | ✕ | **彻底退出进程** —— 一次点击就退 |

（「最大化」「关闭软件」(电源图标)「放到后台」三个按钮**已删** —— 2026-10-25 第二次改口径,
用户原话:「现在就保留两个,一个最小化,一个终止,终止的形状要叉叉,其他的都不要」。
其中「关闭软件」与叉叉**重复**,「放到后台」那个按钮删掉之后,
**把窗口藏起来**改用 **Alt+F4 / 任务栏右键「关闭窗口」**。)

⇒ 「点叉之后窗口找不到了」在旧版本才会发生(那时叉叉 = 「放到后台」)。
**现在叉叉 = 直接退出**,窗口没了、进程也没了 —— 这是**设计如此**,不是故障。

窗口藏起来之后(Alt+F4 / 任务栏右键),**任务栏没有图标**了。找它有三条路:

1. **托盘图标**(右下角系统托盘里)—— 左键点一下 ⇒ 窗口回来;
   右键 ⇒ 菜单:「显示窗口」/「退出程序」。
2. **再运行一次程序** ⇒ 单实例回调把已有窗口叫回来。
3. 都没有 ⇒ 托盘区是不是被折叠了(点右下角那个「^」展开隐藏的图标)。

### 彻底退出

现在有**两个**入口(2026-10-25 第二次改口径后):

1. 右上角**叉叉**(=「终止」)—— **一次点击就退**,最直接;
2. **托盘右键 →「退出程序」**。

⚠️ **Alt+F4、任务栏右键「关闭窗口」都只是隐藏窗口**(与 macOS 的红绿灯同口径)
⇒ 用这两个方式关,进程还在,窗口也还在托盘里能叫回来。

### 托盘图标不见了

| 日志 | 含义 |
| --- | --- |
| `托盘图标已创建` | 正常 |

## Windows 上「把密文还原成明文」不生效(2026-10-26 起形态变了)

Windows 线现在**不用扩展**了：桌面程序**自己起一个 Edge**，用 CDP 把页面守卫注进去
（见 [ADR-0030](../06-决策/ADR-0030-Windows线改用软件自起浏览器加CDP注入守卫.md)）。
所以排查顺序也跟着变了 —— **先确认用户是不是在那个窗口里用**。

> 上一版（注册表外部扩展）真机走不通：.crx 装上后被验证器禁用
> （`disable_reasons=[256]` DISABLE_NOT_VERIFIED），而且浏览器只在启动时读那份清单
> ⇒ 改完还要用户重启一次浏览器（违反零点击底线）。那条路已经退役。

### 先分清：两条线各自谁在干活

| 平台 | 谁在干活 | 界面上的形态 |
| --- | --- | --- |
| macOS | **桌面程序**（Apple Events 驱动 Safari） | 一个**开关**「Safari 复制修复」 |
| Windows | **桌面程序自己起的 Edge**（CDP 注入守卫） | 一个**开关**「浏览器复制修复」 |

⇒ 两条线界面上的开关位置与长相**完全相同**（最后一页最上面）。

### 排查顺序

1. **开关拨了吗** —— 最后一页最上面「浏览器复制修复」，点「开启」。
   状态文字应是「**已接管**」；如果停在「已开启」，下面会有**失败原因**那行。
2. **在不在「那个窗口」里用** —— 程序会打开**一个自己的 Edge 窗口**，
   守卫只装在**那个窗口**里。用户在**自己平时那个**浏览器里复制 ⇒ 永远是密文。
   这是最容易踩的一条，界面上也写了提示。
3. **浏览器开着吗** —— 关掉那个窗口没关系，程序会重新打开；
   但如果程序自己起不来，开关下面会写失败原因。
4. **登录了吗** —— 首次要在那个窗口里**扫码登录**一次超星。
   没登录 ⇒ 页面打不开 ⇒ 什么也复制不到。
5. **选区是空的吗** —— 页面若用 `user-select:none`，连程序化选区都取不到文本，
   守卫就**无字可改**（日志里记 `copy-no-mapping`）。这一条**尚未在真超星上验过**。
6. **开发者：跑端到端门禁** —— 一条命令把整条链路走一遍：
   ```bash
   cd tauri-app/src-tauri
   cargo test --test cdp_copy_repair -- --nocapture
   ```
   它真起一个 Edge、注入、真字形识别、下发、合成 Ctrl+C，
   并断言**系统剪贴板**里是明文。

### 桌面程序这边还有什么是坏的

| 现象 | 看哪儿 |
| --- | --- |
| 界面提示「Ctrl+D 没抢到」 | 快捷键被别的软件先注册了 ⇒ **快捷键**这条路不通，但**浏览器修复**那条路是独立的，不受影响 |
| ⌃D 在**微信**里不管用(别的软件里正常) | 微信用**低级键盘钩子**抢走了键 ⇒ 我们收不到热键。`diag.json` 里 `registered` 仍有 `Control+D`、但 `hits` **一条都没有** ⇒ 注册是好的,这是**层级**问题 |
| Edge 每隔一会儿自己弹出一个空白标签页、复制出来还是密文 | 恢复流程找不回上次那个浏览器(Chromium 写的 `DevToolsActivePort` 被「转发启动」的进程删了)⇒ 已在 2026-10-27 修掉,见本节与 ADR-0032 |
| 「开始输入」之后字没出来 | 焦点不在目标软件上（点按钮那一刻焦点在**我们自己的窗口**里）⇒ 按提示等 3 秒把光标移过去 |

### 开发者：相关门禁

- `cargo test --test cdp_copy_repair` —— **整条链路**端到端
  （起浏览器 → 注入 → 真字形识别 → 下发 → 合成 Ctrl+C → 剪贴板是明文）。
- `node --test tools/verify/verify-page-guard.cjs` —— 页面守卫本身的回归。
- `node --test tools/verify/verify-frame-bridge.cjs` —— 同源 iframe 的帧桥回归
  （站点换掉嵌套 iframe 之后，映射还能不能送到新那层）。

- `cargo test --test cdp_browser_recovery` —— 盯**浏览器恢复**:

## 浏览器每隔一会儿自己弹出一个空白标签页(2026-10-27 修掉的真实故障)

**症状**:软件自己开的那个 Edge,过一会儿就**自己弹出一个新的空白标签页**,再过一会儿又弹一个;
界面上「浏览器复制修复」那栏可能从「已接管」掉回「已开启」或者报错;
**网页上复制出来还是密文**。

**原因**(根因见 ADR-0032):CDP 连接断了之后,恢复流程只认 Chromium 自己写的
`DevToolsActivePort` 文件;而**同 profile 的第二个浏览器是「转发启动」**(Chromium 单例)
—— 它退出时会把那个文件**删掉** ⇒ 永远找不回上次那个浏览器
⇒ 每约 29 秒重开一个(还多开一个空白标签页),而且**再也连不回去**
⇒ 新标签页没有页面守卫 ⇒ 复制必然是密文。

**怎么确认**(三步,不是猜):

1. 看产品日志:「浏览器已就绪」只出现**一次**,之后一直是「启动 Edge」;
2. 看 profile 目录里**有没有** `DevToolsActivePort` 文件 —— 故障时它**不在了**;
   (Tauri 版的 profile 在
   `%APPDATA%\com.gojocloud.campus-network-connector.tauri\browser-profile`)
3. 那个浏览器其实**还活着**:

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
     Where-Object { $_.CommandLine -like '*browser-profile*' -and $_.CommandLine -notmatch '--type=' } |
     Select-Object ProcessId, CommandLine
   ```

   (命令行里那个 `--remote-debugging-port=` 就是它真正的调试端口。)

**已修**(2026-10-27):恢复时按三条候选找(自己记的端口 → `DevToolsActivePort` → 扫进程命令行),
三条都试过才允许起新的;起不来自己的端口就改连已经在跑的那个;
恢复失败也会**打进日志**。回归门禁 `tests/cdp_browser_recovery.rs`,已接进 CI。

⚠️ 装了**旧包**的用户仍会看到这个现象 ⇒ 升级到新包即可。

## Windows 上偏卡顿(2026-10-24 新增)

用户报「Tauri 版有点偏卡顿」。根因与修法见 ADR-0026,这里只写**怎么查**。

### ① 先看窗口被改了几次尺寸

原生侧记了 `FIT_RESIZE_COUNT`:**实际**改过几次原生窗口尺寸,
出现在 `get_native_status` 的 `fitResizes` 字段 ⇒ 前端每 3 秒写的 `diag.json`
(`~/Library/Application Support/com.gojocloud.campus-network-connector.tauri/diag.json`;
Windows 上是 `%APPDATA%\com.gojocloud.campus-network-connector.tauri\diag.json`)
会带着它,在 `nativeStatus.fitResizes` 里。

- **切一步只 +1** ⇒ 贴合内容那条链已经一次算准(修好之后应该就是这样);
- **切一步 +十几** ⇒ 还在绕圈:窗口高度与视口高度互相决定
  (内容区 `max-height:65vh` ↔ 运行时 `set_size`)。

### ② 再看是不是「每帧都在重排」

Windows 上窗口是**透明 + 无边框 + 置顶**的,每改一次尺寸就是一次 WebView 整页重排,
代价比 macOS 高得多。所以「改的次数」比「改的大小」更要紧。

### ③ 顺带看有没有别的反复动作

`diag.json` 每 3 秒写一次,内容是前端的定时快照:
`contentMetrics` 那几栏(内容区可视高度 / 内容高度 / 有没有被裁)能看出
「内容是不是被塞进滚动条里了」。

## 浏览器一个接一个自己弹出来 / 起来的那几个「根本就不能用」(2026-10-27 修掉的真实故障)

**用户当时看到的原话**:
「只要我打开了，他就反反复复拉起浏览器，而且拉起浏览器一直都是失败，根本就没有一个窗口，起来的浏览器根本就不能用」。

### 怎么判断是哪一类

| 你看到的 | 多半是 |
| --- | --- |
| 窗口**一个接一个**弹出来,每次都是**新的空白窗口** | 「用户关掉了窗口,软件又给弹一个」—— 2026-10-27 之前的老行为 |
| 窗口弹出来但**里面是空的/白的**,点不动 | 页面被守卫冻住了 / 那个标签页的映射没到位 |
| **一个窗口都没有**,但任务栏有图标 | Edge 起了但窗口没显示(虚拟桌面/被别的窗口盖住) |
| 浏览器**一个都没起来** | Edge 路径不对,或调试端口起不来 ⇒ 看下面的日志 |

### 日志在哪

- **浏览器自己的输出**(这才是关键 —— 2026-10-27 之前它被丢掉了):
  - Electron: `%APPDATA%\xyw\browser-profile\browser-stderr.log`
  - Tauri: `%APPDATA%\com.gojocloud.campus-network-connector.tauri\browser-profile\browser-stderr.log`
- **我们自己记的调试端口**:
  - Electron: `%APPDATA%\xyw\browser-profile\simuinput-cdp-port.txt`
  - Tauri: `%APPDATA%\com.gojocloud.campus-network-connector.tauri\browser-profile\simuinput-cdp-port.txt`
- **App 自己的日志**:Electron 看 stdout(开发模式下从终端启动就能看到);
  Tauri 看 `diag.json`(`%APPDATA%\com.gojocloud.campus-network-connector.tauri\diag.json`)。

### 现在是什么行为(2026-10-27 修完之后)

- **你自己关掉那个 Edge 窗口** ⇒ 软件**不会**再自动弹一个;
  界面上的「浏览器复制修复」那一栏会出现
  「浏览器已关闭 —— 本软件不会自动再弹一个」+ 一个 **「重新打开浏览器」** 按钮。
- **浏览器崩了 / 被强杀** ⇒ 仍然**自动恢复**(退出码非 0 ⇒ 不是「你关的」)。
- **连着 3 次起不来** ⇒ 软件**停下来**,并把原因报在界面上(不再无限重试)。
- 界面上**只起一个**浏览器:并发调用也会被「单飞锁」合成一次。

## 分不清自己测的是 Electron 版还是 Tauri 版 / 窗口标题显示「模拟输入」(2026-10-27 修掉的真实故障)

**用户当时看到的原话**:
「Electron版本和那个版本，你根本就没有区分，让我测试」。

### 怎么判断是不是这个问题

| 你看到的 | 说明 |
| --- | --- |
| 界面左上角有「Electron 版」/「Tauri 版」小字,但**任务栏悬停提示 / Alt+Tab 里两个都叫「模拟输入」** | 窗口标题被前端页面的 `<title>` 顶掉了(2026-10-27 之前) |
| 托盘提示也显示「模拟输入」 | 托盘提示没设对 |
| 左上角**根本没有**小字 | 版本徽标没渲染出来(前端没更新) |

### 根因(为什么「源码里写了标题」不等于「窗口上真是那样」)

- **Electron**:默认行为是「**页面标题一变,窗口标题跟着变**」
  (事件 `page-title-updated` 默认就会改标题)⇒ `main.js` 里写的 `title` 被顶掉了。
- **Tauri v2(Windows)**:**平台覆盖配置** `tauri.windows.conf.json`
  会**整个替换** `app.windows` 数组 ⇒ 真机上用的是**它**那份,
  改主配置 `tauri.conf.json` **不生效**。
  (2026-10-27 真机抓到:两份配置里只有覆盖文件在说话。)

两个版本的前端 `index.html` 里当时都写着 `<title>模拟输入</title>` ⇒ 两个窗口标题一模一样。

### 现在是什么行为(2026-10-27 修完之后)

- 窗口标题 = **模拟输入（Electron 版）** / **模拟输入（Tauri 版）**
  (任务栏悬停提示、Alt+Tab 里都能看出来);
- 托盘悬停提示同理;
- 界面左上角有常驻徽标;
- 安装名 / 开始菜单名:「模拟输入-Electron」/「模拟输入-Tauri」。

### 开发者:相关门禁

- `node --test tools/verify/verify-build-flavor.cjs`(两仓各 5 条:
  徽标存在 / 界面渲染 / 托盘与标题同名 / 安装名 / **`<title>` 不许被顶掉**)
