# 故障排查

## 「模拟输入/输入源/录制」按钮点了没反应

1. 看界面顶部有没有红色告警条(原生模块加载失败)
2. 命令行看日志:
   ```bash
   grep "\[native\]" /tmp/app.log     # 或从终端启动 App 直接看输出
   ```
3. 检查安装包:
   ```bash
   node tools/verify/verify-package.cjs "/Applications/模拟输入.app"
   ```
   看「原生模块已解包到 app.asar.unpacked」是否 ✅
4. 常见原因:**只换了 app.asar 没换 app.asar.unpacked**(见 ADR-0003)

## Safari 复制修复不生效

> 下面这套步骤是 **Tauri 版**的。Electron 版的数据目录、诊断文件、脚本都不一样,
> 别把两边的命令混着用(2026-10-22 这次排查就被 Electron 的路径带偏过)。

按顺序排查:

1. **功能开关是否开着**:界面「Safari 复制修复」= 开启
2. **App 是不是退出了**:关窗口不该退出(macOS 惯例)。看进程:
   ```bash
   pgrep -fl simuinput-tauri
   ```
3. **目标页有没有被接管**:页面上应有 `window.__copyRepairGuard`。查:
   ```bash
   osascript -e 'tell application "Safari" to do JavaScript "String(!!window.__copyRepairGuard)" in tab 1 of window 1'
   ```
   - `false` → **守卫根本没装上**(注入失败),看第 5 步的 `lastError`
   - `true` → 守卫在,继续看第 4 步
4. **映射有没有送到页面**:守卫里 `window.__copyRepairGuard.mappings` 应有内容;
   复制时若打出 `copy-no-mapping`,就是映射没到(看第 5 步的 `mapping` 字段)
5. **看诊断文件**(字段含义见下):
   ```bash
   cat "$HOME/Library/Application Support/com.gojocloud.campus-network-connector.tauri/diag.json" | python3 -m json.tool
   ```
   - `safariRepair.enabled` — 开关状态
   - `safariRepair.injected` — 这一轮有没有处理到标签
   - `safariRepair.lastError` — 致命错误(权限/注入失败/参考库缺失)
   - `safariRepair.mapping` — **映射没建起来的原因**(取字体失败/分析失败/映射为空);
     这三种以前全是静默跳过,只看 `enabled` 会以为一切正常
   - `safariRepair.mappingScopes` — **逐个作用域**的映射结果(保留 12 条);
     只留"最后一次"会把真正出问题的那条盖住(页面上常有五六个作用域)
   - `safariRepair.safariRunning` — Safari 在不在跑(`false` = 没开,中性状态不是错误)
   - `safariRepair.runningProbe` — **判活查询的原始结果**;
     看到 `查询失败: …` 就说明判活这一环断了(见下面第 7 步)
   - `safariRepair.poll.lastProbe` / `pollCount` — 轮询看到几个标签、还在不在跑

> ⚠️ **`diag.json` 是前端每 3 秒写一次的快照。**
> App 窗口不可见时,WebView 的定时器会被系统节流 → **文件停在旧值**,
> 看着像「功能死了」其实是「界面没在刷新」。
> 排查时先把 App 窗口亮着再看这个文件(2026-10-22 就被这个坑过一次:
> 误以为后台轮询线程死了,其实它好好地在跑)。

6. **是不是没等到映射**:刚打开页面 1 秒内复制可能还没建好映射 → 等 2 秒再试
7. **判活查询是不是断了**(2026-10-23 真实故障,ADR-0015):
   老口径问的是 `System Events`,那要**另一份**自动化授权,
   用户从来没被提示过 → 查不到 → 被判成"Safari 未运行" → **整个功能静默停掉**。
   症状是:`lastError` = "Safari 未运行"、`poll.lastProbe` **全空**、
   但 Safari 明明开着很多标签。现在改用 `application "Safari" is running`,
   `runningProbe` 字段会直接显示查询结果;再不行就查
   **系统设置 → 隐私与安全性 → 自动化** 里有没有本 App 对 Safari 的授权。

### 换题后立刻复制,还是密文(等约 0.4 秒就变明文)

**这不是功能坏了,是分析还没完成。**
换到**全新字体**(新的 data URI)时,字体分析要重跑一遍:
原先串行很慢(当时实测 11 秒),并行化之后更快。
⚠️ **那两个数是 debug 构建量的**:release 下同一份真机字体只要 **13ms**(debug 慢 25 倍)。
**所以"等分析"从来不是等 2 秒的原因** —— 真正的原因是**映射下发**要 2 秒(见 ADR-0016)。
这段时间里页面上一份映射都没有 → 复制出来必然是密文。

- 已缓存的字体 → 立即可用
- 全新字体 → 稍等再复制。**现在正常的等待是 0.1~0.5 秒**(实测:87~532ms 就能出明文);
  超过 **1 秒**还不行,查 `safariRepair.fastPoll`(快通道是不是活着、有没有盯住那个标签)
- 换题**不换字体** → 映射直接复用,没有这个窗口

### 换题后第 1 次复制成功、第 2 次复制出密文(ADR-0017)

**先分清是哪种"密文"**:

- **整段都是密文** → 是"这个作用域的映射压根没建起来" → 看下面第 4 步
- **字是乱的但顺序对** → 那是**写错字**,属于更严重的一类 → 见"宁可留错字,绝不写错字"

这一轮在真机上查到**三个根因**(ADR-0017 有完整推导)。现场怎么认:

| 现场现象 | 根因 | 怎么一眼看出来 |
| --- | --- | --- |
| **App 重启后,页面不再上报已有的作用域** | 「送到了就不重报」**用错了账本**:拿页面的 `mappings` 判断"App 知不知道" | 页面里 `window.__copyRepairGuard.deliveredAt` 是空的、`mappings` 却有值 → App 永远学不到 → 快通道是瞎的 |
| **换题后守卫扫到 0 个作用域**(`pageScopes=0`) | 站点顺序是"先注入 @font-face → 再渲染题目文字",签名先到 → 这次扫到 0 个 → 之后签名不再变 → **永远不再重扫** | 手动把 `window.__copyRepairGuard.fontSig` 清空再扫一次,**立刻就发现了** → 说明是**触发条件**的问题,不是字体读不到 |
| **新题目的作用域沿用了旧字体的映射** | 字体指纹用**取样哈希**,而混淆字体"结构相同、字形不同" → 撞车 | 作用域 key 里的指纹:真机上**同一份字体**,取样是 `datagi2tog`、整份是 `data2cozfw` |

**现场能做的三件事**:

1. **App 学到这个作用域了吗**:`diag.json` 里 `safariRepair.fastPoll.cipherTabs` 应 ≥ 1。
   为 0 → **没有作用域被登记进快通道**(多半就是第一个根因)。
2. **页面在持续上报吗**:`window.__copyRepairGuard.reportedAt` 应该**一直在动**。
   App 重启后如果它卡住不动 → 就是"App 知不知道"这本账没被清(第一个根因)。
   `deliveredAt` 有值 → App 已经确认过 → 页面**不会**再报(这是正常状态)。
3. **指纹是整份哈希吗**:换两次题,作用域 key 里的指纹应当**跟着字体变**;
   两次一模一样 → 撞车了(取样哈希)。

**修完之后的验收口径**(真机,真实学习通作业页):换题后复制 **0/4 密文**(和参考明文比),
快通道周期 **205ms**(工作 110ms),映射从零到页面 **116~705ms**。

### 守卫日志里找不到「这次复制走了哪条路径」(日志被 pending 冲光)

**症状**:想查某次复制走的是 `copy-repaired` 还是 `copy-no-mapping`,
但守卫日志里**一条复制记录都没有**,只剩下一堆 `pending`。

**原因**:日志是 **200 条的环形缓冲**。'pending' 是**每轮**都会发生的事
(App 还没确认过 → 每轮重报),每轮都记一条的话,三十来秒就把缓冲冲光。

**现在的行为**(ADR-0018 之后):'pending' **内容没变就不重复记**,变了才记一条。
所以正常情况下日志里 `pending` 只有一两条,复制记录不会被挤掉。

**如果还是被冲光**,按这个顺序查:

1. **页面里的守卫是第几版**:
   ```bash
   osascript -e 'tell application "Safari" to do JavaScript "String(window.__copyRepairGuard && window.__copyRepairGuard.version)" in tab 18 of window 1'
   ```
   版本比 App 里的旧 → 页面还留着旧版守卫(旧版每轮都记 pending)→
   等 App 重新注入它(每 5 轮一次,约 1 秒),或直接刷新那个标签页。
2. **是不是还有作用域一直没被 ack**:看 `reportedAt` 与 `deliveredAt` 的差集。
   差集里剩下的就是 App 还没确认过的作用域 —— 每一个都会每轮重报。
   - `...#nofont` 的普通字体 → **正常**(新版守卫根本不上报它们)
   - `...#<哈希>` 的混淆字体 → App 侧在处理它(看 `safariRepair.mapping` 的失败原因)
3. **App 侧的失败原因**:`safariRepair.mappingScopes` 里逐条写着
   「取字体失败 / 分析失败(负缓存) / 映射为空」。
   分析失败进负缓存 → 10 分钟内不再重试 → 这段时间里那个作用域会一直重报。

### 复制出来还是密文,但守卫明明在(看守卫版本对不对)

页面上可能留着**上一任 App 注入的旧版守卫**。守卫自己能按版本号就地升级,
但**前提是有人重新注入它**。

- **Tauri 线**:每 5 轮强制重注入一次 → 版本一变就升级(约 1 秒内)
- **Electron 线**:现在会**直接比对版本**,对不上就立刻重新注入

查版本的办法同上一条第 1 步。**版本对不上却一直没换**,说明重新注入这条路断了
(注入失败会记在 `safariRepair.lastError`)。

### 守卫装上了,但复制出来还是密文

看 `safariRepair.mapping` 字段:

- `取字体失败(url): …` — 字体下载不到(跨源/需要鉴权/地址变了)
- `分析字体失败: …` — 拿到的不是合法字体文件
- `映射为空(字体 N 个码位,都没认准)` — 字体不是混淆字体,或识别置信度不够
  (置信度不够时**故意不改** → 宁可留怪字,绝不写错字)

## 复制出来的还是怪字,但界面显示正常

说明字体识别失败。查:

- 该作用域的字体是否可读(`@font-face` 在跨源样式表里就读不到 → 不还原)
- 识别置信度不够时会**故意不改** → 宁可留怪字

## 复制只修好一半(前半句明文、后半句密文)

这是 2026-10-21 修掉的真实故障(根因见 ADR-0005):查表要两样东西,
"这个字画成了哪个字"来自主进程的映射表(按字体整份下发,不会过时),
但"这个字属于哪个字体作用域"曾经是**采集缓存**——采集比复制慢一拍,
于是**刚选到、还没采集过的新密文字**查表落空 → 原样进剪贴板。
早先选过的字在缓存里 → 修好了(所以看起来"只修好一半")。

**现在复制时当场按当前选区解析作用域,不再依赖缓存。**
如果又出现同样现象,先确认页面里的守卫版本:

```bash
node tools/lab/diag-frames.cjs chaoxing        # 看每层 frame 的守卫状态与作用域
node tools/lab/diag-apply.cjs <tab> judge      # 逐字复算查表路径,看是谁落空
node tools/lab/verify-fastcopy.cjs --tab <tab> # 清空采集缓存后立刻复制,必须全还原
```

`verify-fastcopy.cjs` 是这个故障的**回归测试**:它清空采集缓存再复制,
旧守卫会红(剪贴板留原样密文),新守卫必须零残留。

## 打包后 App 起不来 / 功能全废

跑 `node tools/verify/verify-package.cjs`,逐项对照。

## 标签页序号对不上

Safari 的标签序号会变(关标签/重排)。**不要用固定序号**,用 URL 定位
(`tools/verify/verify-app-e2e.cjs` 里是按 URL 找的)。
